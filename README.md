## 功能與格式

- 匯入 GLB，保留原件，建立工作副本。
- 三種匯入共用分組規則：牆壁一組、地板一組、每件家具獨立；材質一鍵配置每組搜尋一次，雙擊後仍可細調子元件。舊案可在一鍵配置內按「整理牆地分組」。
- 在 2D 平面或 3D 選取整組家具；單物件展示可選子物件，修改基本色、粗糙度及材質需求。
- 平移／水平旋轉／刪除家具、配置或綁定光源、預覽近似光影。
- 編輯畫布鋪滿可用區域：左側工作區、上方工具列、半透明詳細編輯欄可各自收合，並記住偏好。專注模式可暫時收起面板，離開或按 Esc 恢復；另提供全螢幕與置中顯示。收合保留選取、縮放與鏡頭，不重新載入模型。
- 02 編輯工具列左側切換 2D／3D，右側依序放新增、一鍵配置及復原；觀看點的一鍵配置目前為停用預留按鈕。配置參數收於「一鍵配置設定」，未完成物件可由旁側按鈕快速定位。
- 02 編輯分為「材質、門、裝飾物、光源、觀看點」。材質／裝飾物頁可在 2D 框選新增範圍，輸入需求搜尋模型或貼上 BlenderKit 模型頁網址，核對後下載替換；新增物件可移動、旋轉與刪除。
- [門編輯](docs/DOOR_EDITOR.md)：兩點新增門、五種門型、雙擊單門展示、門框／門片材質、側向與順逆時針即時預覽；Agent 配置已有門洞，保留不確定項目。
- 在 3D 單物件展示請 Agent [配對 BlenderKit 家具與材質](docs/BLENDERKIT.md)：免費優先、付費候補；保留來源網址，選定後在工具內下載並替換。
- 在「光源」預覽並配置室外日光、天花燈具及綁定光源；在「裝飾物」的自動建議中安排桌面用品、花瓶、鍋具與地毯，再由 Agent 找免費 BlenderKit 模型。位置依模型範圍與用途規則推算，需在 2D／3D 核對；不是自動完成室內設計驗收。
- 「一鍵配置」可按整屋、空間或家具類型批次配對；支援共用／個別文字與圖片風格。自動下載免費候選並建立第一版，備選保留連結；全部家具確認後才清理未使用模型。
- 配置視窗分為「範圍與風格、物件配置、輸出結果」；Agent 整理用途、尺寸來源與使用側，未知尺寸不強迫符合占位高度。找不到適用候選時，可為支援用途生成概念家具，依檢查錯誤有限次修正。
- 單物件「選擇並替換」也會核對尺寸與碰撞；必要時請 Agent 修正同一候選，通過後採用新修訂。已確認尺寸、原件與必要家具保留，不能安全修正會列出原因。
- 拖曳觀看點、設定多個效果圖方向與雙向連結。
- 確認後產生 2:1 全景及透視效果圖，保存修訂、工作日誌及舊成果。
- 整合輸出可啟用 [整屋試圖與 Agent 受控修正](docs/SCENE_REVIEW.md)：逐鏡位看圖、有限次修正與重驗；問題與預覽保留，採用後才改編輯修訂。
- 整合輸出也可先選一個觀看點做 [寫實化精修](docs/REALISM_REFINEMENT.md)：依原生證據與試圖微調材質、布料、簡化櫃體表面、示意窗景、證據足夠的天花補面及攝影取景；比較後採用新修訂，再輸出正式尺寸。模型細節不足會明示，不保證僅靠材質即可達到攝影品質。
- 02 編輯的五個頁面使用共用工具列；「一鍵配置設定」預設收合，保留配置範圍、風格與個別參數。材質的確認／結果仍沿用原有視窗；裝飾物與光源保留逐項配置結果與未完成原因。
- 選用 Codex App Server 執行材質候選、試圖判讀及受控瀏覽器能力測試。
- 平面確認頁新增選用 **AI 空間配置**：依生活需求提出家具與動線，經幾何檢查及人工採用後建模。

## 安裝需求

已有舊版環境時，更新後重新執行下方 Python 安裝及前端建置；配置檢查新增 `shapely==2.1.2`，由安裝命令自動安裝，不需額外 DB。

| 工具 | 版本／用途 |
| --- | --- |
| Git | Clone 原始碼 |
| Python | 建議 **3.11.x**；宣告接受 3.11–3.13，其他版本未完成同等驗證 |
| Node.js／npm | **24.x**，用於建置及前端測試；建置後不需 Node 常駐 |
| Blender | **4.5 LTS**，須能執行 Cycles |

CPU 可以渲染；相容 NVIDIA GPU 會嘗試 OptiX，否則使用 CPU。大型模型的記憶體與時間取決於場景。本 repo 不附 Blender 安裝包。

## 從 clone 到啟動（Windows PowerShell）

命令都在 repo 根目錄執行。

```powershell
git clone https://github.com/DingHungD/roomweaver-studio.git
cd roomweaver-studio
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c requirements-lock.txt -e ".[dev]"
npm ci --prefix frontend
npm run build --prefix frontend
```

安裝 Blender 後，將以下路徑換成自己的 **blender.exe**；若已在 PATH 可省略環境變數。

```powershell
$env:INTERIOR_BLENDER = "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe"
.\.venv\Scripts\roomweaver.exe doctor
.\.venv\Scripts\roomweaver.exe serve --workspace workspace
```

開啟 **http://127.0.0.1:8765/**，首先看到「我的專案」。按「＋新建專案」選一個空白資料夾，名稱預設為資料夾名稱，可自行修改；確認後才建立專案並進入「01 匯入」。三張卡片主區域可選檔，卡片內也有 Project04 的「開啟範例」。圖片仍需明確啟動 Agent 辨識，平面建模與出圖也須確認。這些命令不需啟用 PowerShell 虛擬環境腳本。

`--workspace` 是應用的工作佇列、資料庫及專案登記位置；使用者選定的專案資料夾可以放在其他位置。輸入批次、設定、修訂與模型／渲染成果保存在該專案底下，不會因再次匯入而多建立一張專案卡片。完整備份需同時保留專案資料夾及應用 workspace。

資料夾選擇使用本機系統視窗，需要 Python Tcl/Tk 與桌面環境（本機驗證為 Tk 8.6）。Python 安裝未含 Tk 時需補裝；服務在無桌面的遠端環境中無法使用這個本機選擇器。選取及建立時都會拒絕非空資料夾，不覆蓋既有內容。

若只使用 `INTERIOR_BLENDER`，每次重新開終端須重新設定，或把 Blender 加入自己的 PATH。建議首次啟動時加上 `--blender "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe"`（替換為實際路徑），例如 `python -m interior.workbench serve --workspace workspace --blender "C:\path\to\blender.exe"`。工具會存入該工作區的 `artifacts/workbench/local/runtime.json`，下次相同工作區啟動會自動讀取，不需重新匯入。優先順序為 `--blender`、環境變數、已存設定、PATH；機器路徑不放入案件設計或 GitHub。`doctor --workspace workspace` 可檢查相同設定。8765 被占用時改成 `serve --workspace workspace --port 8875`，開啟 http://127.0.0.1:8875/ 。不要同時用兩個服務開啟同一份 workspace。

素材配置找不到 Blender 時會在下載前失敗，整批暫停，不會逐一耗盡備選。修正路徑並重啟服務後，按「沿用候選重試配置」可使用既有候選重新建立工作；搜尋結果與失敗紀錄保留，不重新呼叫 Agent 搜尋。

`requirements-lock.txt` 是已測試環境的 **constraints**，用 `-c` 限制版本。基本安裝不會因此安裝全部選用 Agent 套件。

## DWG 自動轉檔（選用）

「從電子平面建立」可直接選 `.dwg`／`.dxf`，平面確認頁的「換一份」也支援這兩種格式。DWG 需另行安裝 [ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter)，工具不隨 repo 發布；DXF 與其他入口不需要 ODA。

DWG也需要免費的[LibreDWG官方Windows版本](https://github.com/LibreDWG/libredwg/releases/tag/0.14)，保留同包DLL及授權檔。解壓後設定 `$env:LIBREDWG_DWGREAD = "C:\path\to\dwgread.exe"`，或在本機workspace的runtime.json新增`dwgread`路徑。不把GPL工具視為MIT元件或隨repo打包；不需購買AutoCAD。本輪驗證0.14，進階物件／圖塊轉換限制見[原生流程](docs/DWG_READING.md)。未安裝或原生／DXF不一致會明確阻擋，原件保留。

Windows 會搜尋 ODA 常見安裝位置與 PATH；其他安裝位置可在啟動服務前設定：

```powershell
$env:ODA_FILE_CONVERTER = "C:\path\to\ODAFileConverter.exe"
```

也可在應用 workspace 的 `artifacts/workbench/local/runtime.json` 加入 `oda` 執行檔路徑，保留其他既有設定。機器路徑不放入專案設定或 GitHub。解析順序為環境變數、runtime 的 oda、PATH、Windows 常見安裝位置；明確設定失效會顯示錯誤，不偷偷改用另一個工具。

原始 DWG 保留於專案 `sources/workbench/<批次>/`；轉出的 DXF、來源雜湊與轉換日誌位於 `runs/plan-conversion/<執行>/`，平面確認修訂仍在 `workflows/plan-import/`。轉換採 ACAD2018 ASCII DXF、不啟用 audit 修復、不更改設計尺寸。轉檔本身通常需數秒，逾 120 秒會停止並保留紀錄；原始檔及轉出的 DXF 各限制 10 MB。轉檔失敗不取代現行平面。

**格式轉換不等於完整設計驗收。** 匯入會自動整理模型空間：ARC／CIRCLE／bulge 等曲線轉為有弦差上限的折線；HATCH 保留邊界與孔洞；尺寸／文字與填色顯示元件保留為參考。只有至少八成 LINE 端點位於 Z=0、起伏小於圖幅 5% 且無立體實體時，才將偏離高程投影為衍生 XY；傾斜 OCS、多樓層或立體內容繼續阻擋。原始檔、XY 與尺寸端點不回寫。

地板優先沿封閉線網、空間標籤與填色邊界推定，必要時用尺寸端點及四側線圖建立橙色虛線候選；保留孔洞，不用凸包填滿。候選經受約束三角化與凸片合併，仍由使用者核對推定範圍。圖塊、外部參照、牆線寬等不確定內容會列出原因；展開後最多 2,000 元件／20,000 頂點。

「CAD 自動整理」列出尺寸標註、處理數量與真正待確認項。單位有歧義時只提示，不憑家具大小自動定案；使用者可在圖面單位下拉選擇後確認並保存，已確認單位會鎖定，避免改動既有尺寸解讀。舊版 CAD 平面第一次進入 UI 會以新修訂整理，保留原件與原有人工設定；專案卡片查詢本身不觸發整理。只有平面檢查與使用者確認完成後，才會建立 3D。

## 第一次操作：三種範例入口

請先看 [三個範例的操作手冊](examples/README.md)：

| 入口 | 檔案 | 用途 |
|---|---|---|
| 從圖片建立 | [project04-plan.png](examples/from-image/project04-plan.png) | Codex 辨識、確認尺寸與疑點後建立概念 3D |
| 從電子平面建立 | [project04-plan.dxf](examples/from-dxf/project04-plan.dxf) | 確認用途、牆厚與高度後建立概念 3D |
| 開啟 3D 模型 | [project04-apartment.glb](examples/from-3d/project04-apartment.glb) | 直接編輯既有家具、材質與燈光 |

首次只想體驗編輯，先建立專案，再點「開啟 3D 模型」卡片內的「開啟範例」，會在該專案的 sources/example 批次中複製原生 BLEND／GLB 配對並保留 HDRI。點卡片主區域則直接開啟電腦選檔視窗，只匯入使用者選定的 GLB。

首頁卡片會恢復專案的平面收件、模型準備、已保存編輯分頁或整合輸出；來源與舊修訂保留。可用「← 我的專案」返回，未保存的場景／平面會提供保存或捨棄選擇；未送出的圖片補充說明只提示保留／捨棄，不會替你啟動 Agent。內建範例只有 Project04；保留 repo 的 `examples/` 目錄，否則範例按鈕會停用並提示未安裝。

編輯後先確認光源與觀看點，再點「確認編輯，前往整合輸出」。低解析試渲染為 1024×512 全景、640×480 效果圖；正式為 4096×2048、1600×1200。這裡的原生預覽為 1200×900、48 samples Cycles。配對範例附 Living／Master 兩個觀看點，可出兩張全景和兩張效果圖。

2D 用方向鍵／WASD 平移、滾輪縮放；3D 用 W/S 前後、A/D 水平側移、E 上升／Q 下降。雙擊物件進入單物件展示、拖曳旋轉；操作時先將焦點放在畫布。

2D 預設為 **B 柔光平面**：保留地板／家具貼圖、法線及粗糙度，使用獨立柔光、固定曝光與柔化陰影，並補上可辨識牆體的水平切面。原 GLB 的高強度日光不會疊加到編輯畫面。編輯介面統一使用柔光平面，不再提供額外輪廓切換。

平面柔光是即時 WebGL 近似效果，與 Blender 提案圖的完整間接光仍有差異；不修改案件燈光、原材質或正式出圖。一般 3D 編輯使用獨立補光，光影頁則依已採用的燈光設定預覽。

![B 柔光平面的實際編輯介面](docs/images/studio-plan-soft.png)

平面取景會優先依可辨識的室內地板範圍置中，排除窗外佈景、陽台及切面上方物件；切回 3D 會恢復顯示。自動範圍目前依 `floor`／地板／地坪與室外物件命名判斷；未找到地板時退回其餘可見模型範圍，不宣稱能辨識任意未命名模型的室內輪廓。

GLB 不保存 Blender HDRI 世界設定；要保留原生光影，請用上述配對入口。三套範例使用相同平面，但圖片／DXF 的概念建模不會自動產生精細家具。舊合成案例已移至 `tests/fixtures/legacy-examples/`，供回歸測試與歷史證據使用。

## 使用自己的檔案

### 從 DXF 建立 3D（本機新增功能）

更新後重新安裝 Python 依賴並建置前端（沿用上方安裝命令）；新增依賴為 `ezdxf`，不需 Agent 帳號。

1. 建立或選擇案件 →「01 匯入」→「從電子平面建立」→ 上傳 `.dwg` 或 `.dxf`。
2. 在平面確認頁核對單位、範圍及每個元件用途；可改名稱、高度、離地高度、中心線牆厚與 X/Y 平移。圖層名稱只提供建議，不代表已確認。
3. 按「保存並檢查平面」，修正阻擋項目，勾選範圍確認，再按「確認平面，建立 3D」。
4. 完成 GLB／BLEND 交接檢查後自動進入編輯。新增觀看點、確認光影，再進入整合輸出。

可直接上傳 [Project04 教學 DXF](examples/from-dxf/project04-plan.dxf)，依 [範例手冊](examples/from-dxf/README.md)測試；包含 69 個元件，家具為占位區域。

支援 **ASCII DXF、模型空間、世界 XY 平面、LINE／無圓弧的 LWPOLYLINE**。牆可以是中心線或封閉凸輪廓；地板／家具為封閉凸輪廓；門窗以沿牆直線表達寬度。門窗會實際切出洞口，窗附簡易框；不建立門扇、天花或自動房間分區。提供可調整的初始照明。

上限 10 MB、2,000 個模型空間元件、每元件 100 頂點、合計 20,000 頂點。TEXT／MTEXT／DIMENSION 明示略過；INSERT、圓弧、非零高程、凹輪廓及其他未支援內容會阻擋建模。請先在 CAD 展開圖塊、整理輪廓，不會將錯誤原件替換成範例。DXF 原始座標保留，生成模型以地板範圍移近原點，偏移記錄在 `plan-build.json`。

平面設定保存在 `workflows/plan-import/` 的不可變修訂；重新開啟同案入口可續編。相同確認版本重送只建立一個工作；要修正或重試，先保存新修訂。原件、舊修訂與模型不覆寫。PNG／JPG使用圖片入口；DWG使用上方原生讀取及核對流程，SKP仍需先轉受支援格式。

### 從 GLB 開始

先停止服務（Ctrl+C），建立另一案件，再用同一 workspace 啟動：

```powershell
.\.venv\Scripts\roomweaver.exe new-project MY_HOME --name "My home" --workspace workspace
.\.venv\Scripts\roomweaver.exe serve --workspace workspace
```

在案件選單選新案件，匯入自己的 GLB。ID 使用英數、底線或連字號，顯示名稱可以不同。

先在建模軟體確認尺寸、法線、牆厚、家具名稱及貼圖。名稱／階層與幾何只是分組線索，匯入後仍應檢查；房間不保證能從任意網格自動準確辨認。建議物件名稱清楚且不重複。

原件複製到案件 `sources/`；Blender 工作模型與成果寫入 `runs/`；修改採不可變修訂，不回寫你選取的原始 GLB。大小限制見 [疑難排解](docs/TROUBLESHOOTING.md)。

Codex 使用雲端模型與帳號額度，不是完全離線推論。啟用判圖會傳送試圖及任務所需資訊。憑證由 Codex 管理，不寫入 repo。失敗不自動切換其他付費供應者。Computer use 目前為專用 Playwright 瀏覽器與受控工具，不是控制整個 Windows 桌面。

## 圖片 → 平面確認 → 3D（本機開發版）

1. 在「匯入」選擇案件，再按「從圖片建立」，上傳完整 PNG／JPG。上限 20 MB、2,400 萬像素，最小邊 100 像素；PDF 請先匯出成圖片。
2. 按「連接本機 Codex」，選擇實際可用的圖片模型。可補充尺寸單位、符號意思、圖面已知疑點。
3. 按「請 Agent 辨識」才會將**該張圖片與補充說明**送至 Codex 雲端模型，使用自己的訂閱額度。單純上傳不會呼叫模型；不會改用其他付費 API。
4. 辨識完成後按「核對平面」。原圖與向量輪廓疊合顯示；在原圖點兩個已知長度的端點，輸入公尺並確認比例尺。Agent 建議尺度也必須人工核對。
5. 點選元件後可改用途、名稱、高度、宿主牆與平移；拖曳白色頂點或輸入像素座標可修正線稿。漏辨時使用「補上漏辨元件」，誤辨時將用途改成「略過」。門窗可明確選定牆後按「將洞口對齊選定牆線」。
6. 逐項處理辨識疑點，保存檢查；通過後勾選建模範圍，再按「確認平面，建立 3D」。完成共同交接檢查後自動進入原有編輯流程。

**能力邊界：**這是可校正的概念轉錄，不是自動精準測繪。全圖比例尺不會修正手繪的局部變形；要精準尺寸需再整理 CAD。僅建立直牆、凸多邊形地板／家具占位及門窗洞口；不會生成精緻家具、天花、梁柱完整施工模型或自動完成空間分區。模型漏辨、疑點、宿主錯位都可能需要人工修正。

圖片正規化會處理 EXIF 方向、白底合成透明區與縮小到最長邊 2048；原件保持不變。辨識失敗、停止或服務重啟不會自動付費重試；重新選擇圖片後才可再次提交。保存後可重新開啟同一案件續編；修改平面會產生新修訂，舊模型保留。

設定與辨識證據在案件 `workflows/plan-import/`，原件在 `sources/workbench/`，模型在 `runs/interior-studio/`。平面目前以可編輯修訂 JSON 保存，尚未提供轉錄 DXF 下載。Project03 的私人測試圖不包含在公開範例中。

### 圖片辨識的複核與自動修正（本機開發版）

按「請 Agent 辨識」會執行兩輪：整圖盤點、四個重疊放大區域複核。第二輪同時收到第一輪的幾何檢查，補辨牆、門窗、設備並整理量測端點；使用同一個已選 Codex 模型，不會換供應者。通常比單輪花更多時間與訂閱額度，可停止，服務重啟不自動重送。

確認頁分為原圖疊合、自動處理紀錄、尺寸端點表、需要回答的問題。中等信心不再逐件產生確認框；明確語意疑點、低信心重要元件、無法安全對齊的洞口仍保留。洞口只在已指定的唯一牆段且偏差不超過 `min(8 px, 短邊 × 0.008)` 時自動投影，保留前後座標；不延長牆、不猜宿主、不改寫原稿。

清楚長尺寸可預填候選比例尺，仍須確認。尺寸表保存辨識當時的像素比例差額；不代表實測幾何，也不會因修改比例尺而覆寫歷史。全圖比例不一致時保留差異，不自動扭曲手稿、推算標準門寬或聲稱施工尺寸通過。每張圖的顏色、單位與量測習慣需在補充說明提供，不套用範例作者的習慣。

既有草稿及修訂不會被新辨識覆寫。要試新版，重新選擇同一張圖片，產生獨立收件及辨識紀錄；最終建模仍需使用者確認。


### 沿用本案既有確認（本機開發版）

確認頁會顯示「已沿用本案確認紀錄」、已解決／部分已確認的答案與來源。已有明確答案的題目不再要求重複勾選；部分已確認的題目只保留未知端面或用途。尺寸表同時顯示原誤讀與採用值，不把已確認數值誤稱為影像辨識成功。

本版由維護者把同一案件的確認紀錄對應至該版疑點／尺寸 ID，再透過 `/image-plans/{image_id}/refine` 提交。尚無自動搜尋任意資料夾或匯入確認文件的使用者介面；不會掃描其他案件套用答案。補充紀錄及圖片會送至指定 Codex 模型，使用訂閱額度。來源文字、來源雜湊及對應範圍保存在新收件中，原稿及舊修訂不變。

疑似數字誤讀可指定原圖文字區域，以放大原向及兩個旋轉方向獨立讀圖，再比對歷史確認。不清楚時保留候選；確定的歷史量測優先，但不猜量測端面、不全圖拉伸。比例尺與最終建模仍需確認。接口與限制見 [架構文件](docs/ARCHITECTURE.md#image-evidence-refinement-v3)。


### 直角重建與圖上答覆（本機開發版）

手繪線用來辨認構件及相對位置，不能把筆跡傾斜直接當成斜牆。已確認的尺寸與量測端面優先；遇到不閉合要保留差異，不能分攤誤差假裝全部滿足。

已知本案為直角格局時，先保存，再按「本案牆角為90°，整理線條」。系統另存校正版，整理牆體水平／垂直、保持共用頂點，門窗沿原宿主同步調整。接近斜向而無法判斷的牆會拒絕自動校正。原圖片及原始轉錄點不變，可疊合比較。

目前校正頁會明示「已綁定尺寸幾筆」。尺寸須先有來源紀錄及兩端構件頂點／方向對應，才能透過校正 API 作精確長度約束；此版尚無滑鼠綁定量測端面的操作介面，也不會自動把文字框當端點。零筆代表僅做角度整理，尚未將各段長度重建為精確實測值。互相矛盾的已綁定尺寸會拒絕套用，修改幾何後也會重新檢查既有約束。

有圖上說明的案件會顯示編號彩框、局部原圖、已知內容、待答事項及回答欄。可轉正檢視、逐題放大，圖內滾輪不捲動頁面。回答隨「保存並檢查平面」保存，尚不自動等同設計確認。也可依編號在聊天一次答覆，讓Agent對照同版標記處理。


### 精確尺寸、A→B 標記與建模阻擋原因（本機開發版）

確認尺寸表分為「已套用」「幾何衝突」「端點未明／未綁定」，並可定位到平面上的綠色尺寸線。修改尚未保存時標為待重新檢查，保存後依當前幾何重新計算。歷史條件算式的差異單獨附來源，不冒稱為這版模型的實測差額。端點不明的尺寸保留原值，不能用全圖縮放或平均分配誤差消除矛盾。

API 的 `opening_width` 綁定可將已確認門窗寬度套用至同一開口兩端；保持宿主牆幾何，位置在既有連續直牆上最小平移以容納寬度，並明示位置仍為提案。超過可用牆長則拒絕，不能延長牆或縮小確認值。一般頂點尺寸仍使用 `vertices` 模式；本版不會從數字文字框猜測幾何端面，量測綁定目前由有證據的服務端操作建立。

在原圖按「畫 A→B，說明端點」，依序點兩點，再輸入內／外牆面、門框、數字與單位等說明，可選擇對應問題。支持旋轉、縮放及刪除標記，保存後可重開。這是保存在修訂 JSON 的使用者證據，不會自動當作比例尺、精確尺寸綁定或已解決問題；尚需後續核對。

「建立 3D」前會列出未保存、比例尺、未確認問題、平面檢查及最後確認的阻擋原因；可按「前往處理」。幾何錯誤旁可定位元件，例如新增門洞尚未指定唯一宿主牆。修改後先保存檢查，通過後才開放最終確認，不會偷偷略過錯誤建模。


## AI 空間配置（本機新增）

入口放在 **01 匯入 → PNG/JPG 或 DXF 的平面確認 → AI 空間配置：家具與動線**。先確認尺度與固定構件，再做功能與家具配置，最後才建立 3D。02 編輯繼續負責材質、光影與觀看點；一般 GLB 未有可靠平面語意，這版不對任意 GLB 自動重排。

1. 匯入後依「核對平面 → AI 空間配置 → 建立 3D」分段操作。已确认的尺度、答覆與辨識紀錄預設收合，需要時可再展開。保存平面並處理檢查錯誤後，點選第二段。
2. 填寫生活需求、逐項必要條件及主要通道寬度。若維護者已匯入本案需求包，會自動帶入並提供來源查閱；平面上的既有答覆一併交給 Agent，不重問已回答事項。既有家具預設不動，需移動的才勾選授權；固定牆、門窗、地板不可變動。
3. 連接本機 Codex，選擇帳號實際可用的模型，再請 Agent 提案。需求與平面座標會送到 Codex；需要 ChatGPT 登入及訂閱額度，最多一輪提案及兩輪修正。
4. 預覽藍色新增／移動家具、橘色操作區、綠色或紅色動線。閱讀逐項需求承接、設計理由、假設與未解事項。
5. 通過程式檢查後，明確接受候選並按「採用配置，另存平面」。重新確認建模，再建立 GLB／BLEND，进入 02 編輯。未採用前原平面不變；提案過期時必須重新提出。

若無法開始，介面會列出未保存修改、平面問題、需求空白、模型未選或需求包過期等原因，可按「前往處理」。無需先勾選第三段的建立 3D 確認，就能提出配置。

檢查包括家具碰撞、室內範圍、牆體、門洞保留帶、通道完整寬度與家具操作區。Agent 修正會收到實測重疊範圍；既有窄門及不連續地板另列為平面限制，不會自動改圖。這些檢查不等於住宅功能、門扇開啟、施工、採購或法規全數通過。Agent 必須列出未解需求，不可用通過幾何檢查掩蓋未知。家具目前包含床、上下舖、沙發、餐桌、書桌、椅子、櫃子、爐具、洗衣機與電視的通用概念模型，尚未接商品庫或自動下載材質。

測試用 [6 × 6 m 工作室範例](tests/fixtures/legacy-examples/layout-study/README.md) 可直接匯入，沒有客戶資料。若已建立 3D 後回到平面重做配置，會建立新的模型基線；既有模型修訂保留，但材質／燈光等後續修改不會自動合併到新模型。

接續修正會保留上一版家具ID、尺寸、需求承接與生活路線，不能透過刪件／縮小換取通過。桌椅採「座位占用」與「淨空操作」分別核對。維護端可另存Agent輔助修正預覽；它與模型執行成功不同，預覽不能直接採用。

## 大型模型操作效能

編輯畫布共用已載入模型、重用 2D 材質並按需繪製。效能目標、實測與首次載入限制見 [效能說明](docs/PERFORMANCE.md)。目前不保證大型模型首次載入低於 500 ms。

選取家具後按「移動／旋轉」，會自動暫停預覽陰影並保留材質貼圖；按「結束調整」恢復陰影。2D 會重用靜態背景，遇到玻璃遮擋或牆體調整則使用完整繪製。這些加速只作用於編輯預覽，Blender 正式出圖仍使用原始模型、材質與照明。

門窗與全案寫實精修：門的種類、尺寸與開向集中於02「門」頁；03寫實化精修可選全案觀看點，逐空間試圖、判圖與有限次回修。01平面疑點、已確認尺寸與最終採用仍由使用者確認。詳見[操作與限制](docs/REALISM_REFINEMENT.md#全案與門窗2026-10-14)。

### 02 編輯工具列（本機 UI 調整）

上方保留保存、置中、工具列收合、專注模式與全螢幕。檢視模式只有選中項顯示深色；新增與一鍵配置採淺色，復原維持原樣。「一鍵配置設定」點選才展開，原有參數與檢查結果仍可查閱，收合不清除輸入。材質設定確認後接續原有物件配置視窗；門沿用右側個別參數。觀看點的一鍵配置與設定目前為停用的預留介面，尚未串接 Agent。

「加強輪廓辨識」與「模型細節準備」的獨立介面入口已移除；本次不修改配置後端、失敗時的套用策略或整合輸出的自動精修。


### 快速找出未完成配置

五個編輯頁的「一鍵配置設定」旁皆提供常駐的「查看未完成項目（數量）」，沒有項目仍顯示（0）。材質、裝飾物、光源列出各自配置結果中的未完成物件，區分需要處理、等待繼續與配置中；已套用或明確保留原件的不列入。材質頁沿用最近一次批次結果，裝飾物／光源使用各自提案的批次。清單按物件身分區分：燈具只列於光源，裝飾物只列於裝飾物；結構牆地仍屬材質，地板上的燈具不會被當作地板材質。

門頁整合缺少種類／開向、原生開門受阻，以及本工具記錄的 Agent 配置疑點和素材替換失敗。觀看點頁整合參數疑點與同一修訂、同一模型的整屋試圖待處理取景紀錄；只有全景、沒有額外效果圖方向也是有效設定。點選清單或圖上編號框會定位，並展開右側對應門或觀看點；有方向識別時一併選取該出圖方向。無法確定位置的任務錯誤會說明原因，不猜測對應物件。（0）只表示目前已取得的檢查沒有待處理項目，不代表 Agent 全屋設計或渲染已驗收。

點清單或畫布上的編號框，可定位到原物件並同步右側詳細編輯；2D 顯示平面框，3D 顯示立體線框。可接續既有移動、旋轉及單物件 BlenderKit 備選操作。這些框只是定位提示，不會新增場景幾何、強制套用失敗模型或更動出圖。無對應物件或已刪除時明示不可定位；同一物件的多個材質問題合併顯示。收起清單即隱藏定位框。


五個編輯頁共用工具列：第二列左側顯示物件／組成或該頁數量，右側放配置設定與既有未完成入口。門頁顯示有效門數，觀看點頁顯示觀看點及雙向連結數；已實作的未完成入口數為 0 仍顯示。兩者在同一區域切換，展開內容位於按鈕下方，按鈕位置保持不變。舊版自動燈具名稱中的地板組成只是燈位定位來源；介面將其顯示為「天花燈具 01」等名稱，保留原有識別與保存資料。使用者自行命名不會被改寫。
