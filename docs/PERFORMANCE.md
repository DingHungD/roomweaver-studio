# 編輯畫布效能

本文件維護共用前端的效能策略與驗證方式。大型模型及測試截图留在本機 `artifacts/viewport-performance/`，不作公開 fixture，也不提交案件資料。該目錄為可重新量測的開發證據，可清理；案件模型、修訂與 Blender 產物不是暫存。

## 回應目標與量測邊界

- 已載入模型的選取、檢視切換與操作：目標 100 ms 內，可接受上限 500 ms。
- 完整模型首次載入另計，包含讀檔、解析、貼圖解碼、GPU 上傳及 shader 準備；目前沒有 500 ms 保證。
- CPU 的 `renderer.render()` 返回不等於 GPU 完成或螢幕已顯示。不可把此數值當成端到端操作延遲或 FPS。
- 不使用閒置畫面之間的間隔推算 FPS；畫布現在只在需要時繪製。背景分頁、隱藏畫布及瀏覽器排程可能延後下一幀。

## 已實作

1. 材質、裝飾物、光源、觀看點共用同一個 WebGL 畫布。移動 portal 容器，保留已解析模型與 GPU 資源；變更模型網址或原生物件分組時才重建。概念家具仍由場景同步新增／移除。
2. 物件選取只更新外框、操作軸與中心，不重新套用整屋材質或刷新陰影。
3. 2D 預覽材質重用；真正換材質時淘汰不再使用的快取。原材質與貼圖保持可還原。
4. 沒有輸入、相機阻尼或拖曳時停止動畫排程與繪製；輸入、尺寸或資料改變時重新喚醒。外框虛線仍由 CSS 動畫顯示。
5. 輪廓線只在開啟「加強輪廓辨識」後建立。超過 3,000 三角面的組成以包圍盒作輪廓輔助，避免對精細家具逐面求邊；原始幾何、柔和 2D 材質及正式渲染不變。
6. 首次貼圖準備分批讓出主執行緒，顯示進度，並預先準備 shader。單張貼圖上傳仍可能超過批次預算，不能宣稱完全無阻塞。

## 本機診斷

以 `/?performance=1` 開啟工作室。效能紀錄只存在畫布 DOM 的 `data-performance` 屬性，不上傳第三方。未開啟參數時不收集樣本。

`loadParse` 為 GLTFLoader 完成時間；`prepare` 為組裝、建立編輯狀態及初始配置；`textures`、`shaders` 分別計時；`firstFrame` 從畫布初始化至第一次有模型的 render 返回。

`interactions` 保存最後 100 筆輸入：`wait` 是輸入至進入 renderer 的等待（含事件處理、React 和瀏覽器排程），`render` 是 renderer CPU 執行，`total` 是兩者相加。它不是 GPU present fence。只操作未儲存的選取與視角即可重測，不需要呼叫 Agent 或 Blender。

重測流程：開啟同一案件 → 選取床／沙發 → 光源 → 觀看點 → 材質 → 3D → 單物件 → 點選子物件 → 2D。核對 `loadParse` 仍只有一筆、觀看點新增可用、子物件選取正常、靜止後 frame 數不再增加；切換模型要重新載入。

## 2026-10-12 本機大型案例

單次序列，196.2 MB、約 239 萬三角面、83 張貼圖；不是跨裝置 benchmark，也沒有做壓力測試或 GPU 完成時間量測。

| 項目 | 修改前 | 修改後代表實測 |
| --- | ---: | ---: |
| 額外模型準備 | 8,007.7 ms | 24.9 ms |
| 第一次模型 render 返回 | 15,636.6 ms | 9,097.5 ms |
| 物件清單選取 | 1,154.8 ms（1 筆） | 59.2／213.3 ms |
| 光源／返回材質 | 每次重載模型 | 260.4／130.9 ms，未重載 |
| 3D／單物件／返回2D | 未量測 | 257.7／107.6／138.8 ms |
| 畫布點選子物件 | 未量測 | 147.1 ms |

同序列有一筆觀看點切換 **1,002.9 ms**（等待 984.3 ms、render 18.6 ms）。先前序列此操作為約 148 ms；原因仍需在持續前景的正常瀏覽器重測，不能只歸因於 GPU，也不能宣稱全數達到 500 ms。首次載入也未達標。測試環境中閒置 rAF 有約一秒的排程間隔；這項觀察不是排除超標樣本的理由。

下一個必要架構改進是產生獨立、可重建的編輯預覽資產（縮小貼圖、適量減面、保留穩定物件 ID），以來源雜湊與設定管理快取，首次先顯示低成本平面，再漸進載入細節。正式 GLB／BLEND 與渲染保留原品質。此預覽資產流程尚未實作，不能把本輪修改當作已完成。

## 2026-10-12 選取、平移與旋轉優化

此輪接續上述版本，優先改善模型已載入後的操作。通用實作不包含案件名稱、物件 ID 或固定平面配置。

- 2D 保留目前相機的顏色與深度快取；選取只更新外框。平移／旋轉時重用背景，只繪製活動家具，以深度維持遮擋。視角、尺寸、採用設定或模型改變後失效。
- 透明／折射物件自身，或與活動家具平面範圍重疊的透明物件，回退完整繪製；移動牆體時同步更新切面。缺少浮點顏色緩衝支援的裝置也回退完整繪製。
- 「移動／旋轉」期間暫停預覽陰影，保留材質、貼圖與幾何；「結束調整」再恢復。預先編譯一般與無陰影的顯示程式，包含快取目標的顯示變體，減少第一次調整停頓。
- 只更新真正改動的物件變換。拖曳中不重建家具幾何、不重建牆體切面；沒有新指標輸入時不持續重繪。
- 點選排除不可見網格與輔助輪廓，使用幾何包圍盒提早排除。材質色彩／粗糙度修改重用材質並保留原貼圖；來源版本更新時釋放舊預覽材質。

### 同機、同模型、同畫布的實際操作

Project03 本機案例：196.2 MB、約 239 萬三角面、65 組物件；畫布 719×450，前景分頁。透過 UI 進行同一沙發的 2D 平移、2D 旋轉、3D 平移、3D 旋轉，每步復原，不保存案件修改。下列是 renderer CPU 提交耗時，**不是 GPU 完成時間或螢幕 FPS**。

| 拖曳類型 | 前 P95 | 後 P95 | 前／後樣本數 | 前／後 draw calls 中位數 |
| --- | ---: | ---: | ---: | ---: |
| 2D 平移 | 59.7 ms | 2.4 ms | 93／9 | 487／28 |
| 2D 旋轉 | 11.1 ms | 1.5 ms | 13／9 | 1429／18 |
| 3D 平移 | 1.3 ms | 1.7 ms | 9／9 | 95／95 |
| 3D 旋轉 | 7.6 ms | 1.4 ms | 63／9 | 80／80 |

移除無輸入的重複繪製後，樣本數會變少。P95 使用 nearest-rank，小樣本時等於最大值；只代表這次操作序列，不是跨裝置效能保證。3D 平移沒有測得提升，原本的 CPU 成本已低。

| 輸入至下一次 render 返回（單次） | 前 | 後 |
| --- | ---: | ---: |
| 清單選取沙發 | 12.6 ms | 11.0 ms |
| 首次進入移動／旋轉 | 22.6 ms | 84.4 ms |
| 2D 平移起始 | 68.1 ms | 3.7 ms |
| 2D 旋轉起始 | 21.0 ms | 3.6 ms |
| 切入 3D | 163.6 ms | 163.2 ms |
| 3D 平移起始 | 6.1 ms | 4.6 ms |
| 3D 旋轉起始 | 7.6 ms | 6.0 ms |

第一次進入調整模式新增背景準備成本，較原版慢，但本次在 100 ms 內。切入 3D 超過理想 100 ms，仍低於 500 ms。首次有模型的 render 返回為 4,882.1 → 4,525.4 ms，**仍有數秒等待**；瀏覽器與磁碟快取會影響載入值，不能直接與上一節不同條件的測量相比。

後續往返檢查發現：無需更新的來源材質版本也被標記更新，造成返回 2D 重編譯、耗時 772.6 ms。已改為只在既有材質的陰影狀態真正改變時更新。最終往返回歸（`roundtrip-final.json`）為：選取 7.5 ms、啟用調整 77.4 ms、切入 3D 132.1 ms、結束調整 9.8 ms、返回 2D 19.8 ms。另有直接畫布點選床的 41.8 ms 紀錄（`picking-final.json`；畫布尺寸不同，不能與表格作配對比較）。

原始量測與截圖位於本機 `artifacts/edit-interaction-performance/`，其中 `before.json`／`after-final.json` 為同條件比較，`comparison.json` 為摘要。中間版本 `after.json` 僅保留調查過程，不作完成依據。測試核對 GLB 雜湊、保存修訂與場景內容未變；本輪未執行 Blender 正式渲染，渲染服務與品質設定均未修改。

### 限制與後續

目前快取屬於畫布生命週期，仍須先載入完整 GLB；平移／縮放整張平面時相機改變，背景仍需重畫。尚未建立離線 2D 圖塊、輕量 GLB、LOD 或分區串流，因此更大型模型的首次載入與相機連續移動仍需下一階段處理。不能保證任何新專案、任意硬體都低於 100／500 ms。

自動回歸使用合成雙家具、透明材質、變換復原、貼圖保留、快取失效與資源清理測試。實際 GPU 畫面另以 UI 驗证，不以模擬 renderer 測試取代人工判圖。

本輪前端 72 項測試通過，TypeScript 檢查及正式建置通過；仍有既存單一 JS 包超過 500 kB 的建置提示。未進行 Agent 或 Blender 實際任務。


## 滿版編輯與面板收合（2026-10-12）

畫布填滿編輯區，左側工作區占用獨立寬度；上方工具與半透明詳細編輯欄是獨立覆蓋層。面板內捲動受限於自身，按鈕不把事件送往畫布。收合偏好存在本機瀏覽器，專注模式暫時覆蓋偏好，退出後恢復；全螢幕由瀏覽器處理，不修改設計。

收合只改投影中心與顯示尺寸，不重建 WebGL、重新載入 GLB 或重設鏡頭位置、方向與縮放。「置中顯示」才主動依目前可用區域重新構圖。畫布快取在投影／尺寸改變後重畫一次。右側面板背景半透明，但不啟用大面積模糊。

Project03 已載入模型測試（1280×720 瀏覽器，畫布 1108×672；收合左側後 1244×672）：選取沙發 22.2 ms；收合詳細編輯 32.4 ms、收合工作區 38.0 ms、收合工具列 29.3 ms。以上為單筆輸入至 renderer CPU 返回，非 GPU 呈現延遲；後續 3D 收合測得 120.8 ms（等待 119.8 ms，renderer 1.0 ms），低於 500 ms 但未達 100 ms 理想值，不能宣稱所有操作皆低於 100 ms。

整段收合過程 loadParse 僅一筆；3D 鏡頭狀態完全一致，2D OrbitControls 浮點更新差異小於 0.000001，選取與縮放不變。專注模式恢復三個面板，全螢幕可進入／離開；960×720 的視窗沒有頁面水平或垂直溢出，詳細編輯在自身範圍捲動。證據存於 `artifacts/editor-full-canvas/`，為本機案件驗證，不發布案件模型或截圖。

新增投影與射線測試確保覆蓋層避讓後，正交／透視相機的目標及點選仍對齊；前端共 73 項測試通過。正式渲染流程未改動，也未重新執行 Agent／Blender 工作。
