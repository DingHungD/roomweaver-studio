# 依現有燈具建立光源

在「光源」頁按 **依現有燈具建立光源**。程式先保存目前設計，再使用 Agent 設定中所選的 Codex／ChatGPT 模型辨認現有燈具。按鈕授權這次送出模型名稱、尺寸、材料名稱與診斷／局部圖；不會於匯入時自行呼叫 Agent，不另選付費 API。

更新程式後請依 README 的啟動方式重新啟動後端並重新整理頁面，避免同一工作區重複啟動服務。

工作可在 Agent 工作清單查看及停止；重新整理會讀回進度。完成後，只在保存版本仍相同且沒有未保存編輯時自動加入光源、保存新修訂。版本不同時保留結果，須依新版本重新配置。原模型與舊修訂不覆寫。

## 行為與限制

- 保留所有既有光源（含關閉、手動、鎖定光源）、曝光及環境模式。已有綁定光源的燈具不重配。能對應的基本 Blender 原生光源優先恢復；原生光源範圍內的燈具避免重複新增。自訂光源節點及超出既有資料契約的原生燈光會拒絕轉換，防止誤以推定值取代原照明。
- 所有未刪除群組均納入盤點，不只以燈具名稱搜尋。每批最多24群組，用原生三角面上／下方診斷投影及名稱、尺寸、材質辨認；大型模型會明示網格抽樣，投影未含貼圖。混合整間房、缺少網格或辨識不清會列待確認；尚不能保證找齊所有燈具。
- 候選逐一產生真實 Blender Cycles 正面、反面、下方局部圖。軌道／多燈頭等細小組成另補最多6組正面與下方近景，保留所有原始網格，只調整取景；近景附世界座標範圍及組成 ID，避免整組圖中燈口太小。Agent 從原生幾何量測的外向表面選 anchor。光源放在該表面外1.5cm，方向來自表面法線。無合適發光表面時保留待確認，不在包絡中心硬加補光。
- 可新增 AREA／POINT／SPOT，每燈具最多8個發光點、場景總計最多200盞。瓦數、色溫、尺寸及配光均為推定，標記「推定光源」，可於現有光源參數調整。不是 SketchUp／V-Ray／Enscape 原光照還原，也不是原廠 IES 或照度分析。
- 發光面量測包含整體外包與原生子組成 BVH；可取得被外罩／支架遮蔽的實際內部燈泡表面，最多256個 anchor，保留向外法線與組成 ID。不補造燈泡或任意開口中心。`tests/fixtures/fixture-lighting/check_inner_surface.py` 已用真正 Blender 驗證外罩及支架阻擋整體射線的反例、內部燈泡、鏡射法線及有界數量。
- 同一原生網格資料塊、相同材質、等實體尺寸的組成，可提供模型內既有推定光源作比對參考；來源光源須反推至該真實表面2mm內，縮放不同或不同資料塊拒絕。Agent 仍需對照圖片並選取目標燈具自己的 anchor，不複製世界座標。後續候選可參考本工作先前已驗證的私有提案；整批完成前不保存設計。此比對不代表取得原廠瓦數或測光資料。
- 光源綁定群組基準座標；移動、旋轉、刪除沿用既有重播機制。沒有新增燈具、改家具材質或位置。02 預覽仍使用原有24盞來源光源／8張陰影圖預算，Cycles 使用所有有效光源。
- 局部看圖只驗證燈具與發光面。加入後請使用「整合輸出」低解析 Cycles 試圖核對整屋照明；此按鈕不代表整屋照度或渲染驗收通過。

## 介面與證據

`POST /api/studio/projects/{id}/fixture-lighting` 接收 `base_revision`、`operation_id`、`model`。同操作識別碼不得換輸入。GET `…/current` 或 `…/{task_id}` 只讀進度；POST `…/{task_id}/apply` 帶原 `base_revision`，可重試且不重複新增修訂。恢復服務會把尚未完成工作標成 interrupted，不自行重新付費／呼叫模型。

每案 `workflows/fixture-lighting/current.json` 是操作入口，`runs/fixture-lighting/<task_id>/` 保存輸入、原模型 SHA-256、盤點、局部圖、Agent 回覆、推定依據與採用修訂。Agent 工作佇列沿用既有 workspace state。程式：`workbench/studio/fixture_lighting.py`、`visualization/fixture_lighting_evidence.py`；UI：`FixtureLightingPanel.tsx`。

共用核心另接受內部 `focus_group_ids`，供案件已辨認燈具的限定複核；空白、未知或已刪除群組會拒絕。仍盤點來源並核對 SHA，但僅對指定群組送出判讀。這是核心／案件重播設定，現行按鈕仍執行全部群組；不宣稱新增公開 API 欄位。
