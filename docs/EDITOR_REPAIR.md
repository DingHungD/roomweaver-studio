# 編輯頁未完成項目修正

五個編輯頁的未完成清單提供「Agent 依原因修正」。選取後先定位物件；有草稿時先走原有版本保存，再建立單一目標修正工作。固定使用 `gpt-6-sol`，不可靜默改付費服務。任務、候選、圖片與舊模型均保留，不執行清理。

## 各類修正

- 材質／家具／裝飾物／燈具：使用失敗原因與原批次風格，僅啟用目標物件，重用既有用途防錯、尺寸適配、免費候選、實際模型檢查、Agent 看圖及有限次候選／概念建模修正。技術錯誤後重試可沿用仍符合當前修訂的候選。
- 門：依原生開門證據判斷；保留既有門洞、已確認門組長度、種類、開向、材質及必要家具。不能在此限制內解決的碰牆會留在清單，不以限制開門角度宣告通過。明確的門框／門片素材失敗可重新配對該組成，最多三個免費候選，檢查後才採用，不碰其他組成。
- 觀看點：只修改指定效果圖的攝影參數；兩輪內實際低解析出圖並由 Agent 看圖，通過後才保存。不能改家具、光源、門或房間；每軸相機位置最多移動一公尺。全景專用點沒有可改的效果圖方向時會說明，不憑空添加。

成功必須有採用後的模型／材質來源證據。Agent 修正依原批次及原任務識別核對；手動選擇候選並成功採用時，也核對當前模型來源鏈、已完成的替換工作、精確物件及全部材質組成，移除舊批次的未完成項目。僅保存網址、尚未採用的試圖、部分材質替換、換回原件均不算完成。之後試用其他候選失敗，不會把仍在使用的成功版本重新列為未完成。

這是依當前設計計算的顯示狀態，不改寫歷史批次。保存新修訂後，材質／裝飾物／光源結果同步刷新；重新開啟仍能核對。手動替換完成代表模型已套用，**不代表已通過 Agent 安裝外觀驗收**；回傳 `installation_verified` 分開記錄。修正期間有未保存草稿時不覆蓋草稿。讀取紀錄不會自動發起雲端任務。

「上次修正未通過 · 查看逐項原因」在未完成清單和右側詳細編輯中列出每次實際模型／安裝失敗及候選用途拒絕原因，不只顯示重試上限。舊修正紀錄會從原有批次證據補讀；再次修正時將具體原因帶入工作，不重新只傳「等待配置」。

未完成項目採一列一卡，卡片內提供定位內容及「Agent 依原因修正」按鈕；點選卡片仍定位並同步右側編輯。進行中的工作說明顯示在對應卡片底部，原有修正、停止及版本驗證流程維持不變。

## 門組 AB 長度

詳細編輯可輸入門組 AB 長度，五種門型皆支援，2D／3D 先用本機幾何即時預覽，再於背景核對原生姿態。此值是**原洞口內的門組長度**，中心、門向與原洞口端點保持不變，兩側用原框材質收邊。允許範圍 50cm 至原洞口寬，最多 300cm；不自動擴洞或切牆。保存即為使用者明確採用的尺寸。Agent 未完成項目修正不會代為變動此值，既有「允許 Agent 微調門寬」仍屬另一個明確授權操作。

## 天花燈具安裝

一鍵配置在下載替換前，Agent 依候選用途與說明判斷吸頂、嵌入或吊掛。不把所有天花燈具都當嵌燈；資料不足會改試款式，不捏造已完成安裝。

原生工具以天花射線和四角採樣核對接面。沒有天花時，僅可沿已有室內地板輪廓、封閉牆體及一致牆頂證據建立裝修面，保留孔洞與露天空間；證據不足會保留未完成。吸頂燈頂部接面對齊；吊燈保留比例與吊線並補頂盤；嵌燈只在可確認的裝修天花做 1–8cm 淺槽，須有足夠厚度及餘量，不切割結構樓板／梁。安裝後再核對接面和其他物件碰撞，不能靠偏移成懸浮來通過。

安裝圖從下方呈現燈體與實際天花接點，略去其他牆體以免遮擋；其他物件碰撞仍獨立檢查，這張局部圖不代表全屋驗收。Agent 仍無法判斷時最多保留舊證據另建一次檢查快照，不能直接忽略看圖問題。

扁平吸頂／嵌燈在安裝前量測實際發光面的方向（世界三角面積 × 可直接讀取的發光強度）。只有主要發光面明確朝上時，才繞燈體中心翻轉，再重新貼合天花、量測尺寸、檢查碰撞並由 Agent 看圖；不以模型名稱猜方向。吊燈、多向或貼圖驅動而無法確定的發光方向保留原姿態交由既有檢查，不任意翻轉；已保存的舊模型不因開啟專案而自動改動。

匯入素材若將 Output Light 放在網格材質槽中，Cycles 可顯示發光，但 GLB 匯出可能變黑。替換及預覽重建時，僅在 GLB 匯出的暫時材質副本補上相容的 Material Output；完成或失敗均還原原槽位並移除副本，原生 BLEND 著色器保持不變。發光材質不烘成一般不發光的色彩貼圖。此修正共用於後續案件，不改寫已保存的舊檔。

預覽材質副本須逐槽替換與復原，不清空再追加材質槽，避免多材質網格的面索引歸零、發光面誤用外殼材質。測試同時核對實際 GLB 發光通道與多個 primitive，以及成功／例外退出後的原生面索引。

未確認尺寸的燈具依安裝方式適配，不強迫把吊燈縮入概念方塊的高度；已確認尺寸及明確範圍上限仍維持原有檢查。安裝證據代表此替換快照的接面，後續改位置／改款仍需重新核對；不等同電路、施工或結構認證。

## 儲存及 API

- `POST /api/studio/projects/{id}/editor-repairs`：`base_revision`、`operation_id`、`category`、`target_id`、來源 `batch_id/task_id`、失敗 `reason`，門素材可帶 `part`，觀看點可帶 `shot_id`。
- `GET .../editor-repairs`、`GET .../editor-repairs/{repair_id}`：讀取狀態與完成證據。修改來源版本時拒絕覆蓋；同操作識別碼重送不重建。
- 案件權威採用仍是不可變場景修訂；`workflows/interior-studio/editor-repairs/<id>/` 保存操作輸入、狀態與檢查證據。模型、檢查圖及下載沿用 `runs/interior-studio/`。
- 首輪同案一次處理一個未完成物件；重啟後中斷工作不自動重新呼叫模型。已有下載／試圖／候選保留。

檢查入口：`tests/test_editor_repair.py`、`tests/integration/test_fixture_mount.py`、`frontend/tests/studio-repair-evidence.test.mjs`、`frontend/tests/studio-door-length.test.mjs`。合成測試與真實訂閱／案件測試須分別記錄。
