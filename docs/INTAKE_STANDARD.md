# 01 圖面理解與基本 3D 交接

所有者：共用匯入功能。適用 PNG／JPG 及經本機轉檔的 DWG／DXF，不以案件名稱、圖面座標或圖層命名作特例。3D 模型入口沿用原有模型交接檢查。

## 使用流程

目前核對工作區的完整操作、疑點答覆、用途分層與深淺配色規則見 [可複用平面核對工作流](PLAN_REVIEW.md)。下列為資料交接順序。

1. 在01匯入來源。DWG由LibreDWG直接讀原件圖層／註解／元件，與ODA衍生DXF核對後交接；Agent只分類並綁定來源，位置由原始邊線推導。[原生規格](DWG_READING.md)。CAD自動整理曲線、填色及有證據的高程偏差，來源不回寫。
2. 核對並保存實際單位／圖片比例尺。已確認數字優先，錯誤 CAD 標頭或手繪線長不能取代已確認尺寸。
3. 模型由頂端「Agent 設定」選擇；初次在「判讀結果」啟動 Agent 判讀，已有候選的重新判讀在「修正」。以 gpt-6-sol 等實際可用的圖片模型讀取本案圖像、幾何、原生文字與尺寸；圖片入口另附原始正規化圖片。不讀其他案件，不自行執行模型生成的程式。
4. 預覽用途分區、牆、門窗及家具盤點。來源 ID、宿主牆、幾何範圍與問題會檢查；最多一次自動複核。判讀工作完成不代表判讀通過。有疑點時列出原因，填補充後可重新判讀。
5. 通過檢查才能按「採用判讀草稿」，另存修訂。分別確認用途區域、牆門窗位置、原有家具，再保存。既有人工修改或尺寸端點綁定不會被新牆圖覆寫；目前會阻擋此種整批採用，需保留原幾何另行核對。
6. 原圖有家具：預設沿用已標註配置，不另跑整屋設計。原圖沒有家具：先用 AI 空間配置提出家具區域及動線，預覽採用後才建模。部分區域缺家具的補充設計仍需另行確認，不能把「存在家具」當作全案配置完整。
7. 幾何與交接都通過後，確認概念高度，建立基本 3D。交接 GLB、BLEND、物件對照與初始修訂；保留用途區域歸屬。家具可為概念外形／占位；未支援的家具不冒充完整模型。01 不下載正式貼圖、不執行最終渲染；材質、家具替換、光源與攝影在 02／03。

## 通用判讀技巧

- **圖層不是用途。** WALL 也可能包含櫃體、設備或符號；原生房名文字優先，不能把整層擠出成牆。
- **雙線牆只建一面。** 取中心線與實際厚度，保留來源線索；不能各擠出一面造成重複。門扇弧線是開門證據，不是曲面牆。
- **門窗要有定位。** 洞口沿宿主牆、端點需對齊。窗框／雙線、門扇及文字等共同佐證；缺口不自動等於窗。沒有證據時記為不確定，而非確認沒有。
- **尺寸與相對線長分開。** 數字尺寸、端點／量測方向與單位分開保存。CAD DIMENSION 與標頭矛盾時提示；未確定端點不能為閉合而改已確認數字。Agent 候選座標仍須核對，不是施工量測證明。
- **地板推定不是既定外框。** 填色、文字與有尺寸支持的區域提供候選；外牆／廚房超出候選時保留差異，不能用任意凸包補滿或裁掉合法空間。
- **家具按整件辨識。** 床、桌椅、櫃、廚具、衛浴設備若原圖畫出或文字指定，應盤點並沿用；一把椅子的組成不是多件家具，獨立床與櫃不能合成一件。
- **基本模型與寫實成品分開。** 高度、門窗細節、未知家具用途仍可待確認；平面確認成功不代表材質、照明或施工驗收完成。

## 檔案與相容性

本案來源在 `sources/`；轉檔證據在 `runs/plan-conversion/`；判讀請求、圖像、結果及採用紀錄在 `workflows/plan-import/<plan>/semantics/runs/<task>/`。平面採用另建不可變修訂；3D 在 `runs/interior-studio/`。新修訂不覆寫原件，不清理舊模型。

房間與元件的採用設定是案件平面修訂；Agent 任務紀錄不作另一份可獨立編輯的設計。API 的 UI 建模請求 `confirmed:true` 執行完整交接檢查。既有 CAD 工程呼叫 `confirmed:false` 仍保留幾何建模相容性，不能把它當作 UI 設計確認；圖片建模仍要求明確確認。

CAD 的語意判讀與 AI 配置需要本機 Codex 登入及圖片模型；GLB 編輯與基本渲染仍可不使用 Agent。不會自動切換另一個付費服務。

通用測試：`tests/test_plan_semantics.py`、`tests/test_image_plan.py`。真實模型判讀與 Blender 實作測試分別記錄；客戶圖不放進合成 fixture。


## 對照原圖自動複核與疑點定位

「對照原圖自動複核」承接同一平面修訂的上次候選、檢查結果及已保存答覆；不是每次重新從空白猜測。保留完整曲線與 HATCH 邊界線、原生文字、尺寸端點及標註位置，來源對照圖不依未確認地板裁切。孤立於圖面標註與本體之外的製圖殘線不參與取景，完整座標仍保留在來源資料包。局部放大圖附回原座標範圍。

未確認的推定地板可提出非凸外框及孔洞，逐邊核對原始線條；若只是漏引用而原線條確實重合，可自動補足來源 ID。任意圖框、大矩形或沒有來源的邊線不能當作地板。已確認地板不允許此流程改寫。採用才新增地板修訂，幾何分解保留面積及孔洞，原始 CAD 尺寸不變。

牆厚門檻只用於牆體，不把家具或窗框的薄部件當作不合格厚牆；也不為通過格式限制而放大物件。除了幾何，還會以牆體及門洞檢查房間是否與主要空間連通：窗不是門，小於製圖容差的縫不是入口。這只是單一住宅平面的拓撲檢查，不是法規或施工驗收。

「自動檢查仍未通過」是程式需繼續處理的原因；「原圖疑點與答覆」只列 Agent 判定確實缺資料的項目。疑點帶 Q 編號、來源 ID、定位框、尚不確定的理由與要回答的內容。點編號／卡片放大，滾輪不捲動頁面。可切換地板外框疊合。已定位、確實需要人的問題會停止自動重試，避免為了完成率任意開門。

答覆可逐項填寫，保存後重新開啟仍保留；「保存答覆並請 Agent 複核」將答覆與原疑點、來源修訂一起提交。可只回答部分，不重問已答覆內容；若與既有證據矛盾，仍需說明並定位。過期平面或其他視窗更新過的答覆會拒絕覆蓋。來源圖與數字不因保存答覆而改動。

同案判讀 run 新增 `raw-pass-*.json`、`review-passes.json`、`focus-*.png`、`questions.svg`／`questions.json`，以及有答覆時的 `answers.json`、`answer-revisions/`。圖像與 SVG 均是原件的衍生檢視，不覆寫 DWG／DXF。格式錯誤也保存原始候選供下一輪修正；舊版僅存在任務事件中的輸出可於下一輪恢復作證據，不能把失敗任務直接改成已採用。

程式測試見 `tests/test_semantic_review.py`，原圖座標映射測試見 `frontend/tests/semantic-source.test.mjs`。真實案件來源不加入通用 fixture。


## 七組02交接補齊與未採用預覽（2026-10-22）

UI 的原圖判讀／複核現在提出同版幾何候選後，接續有界的gpt-6-sol交接增量審查；舊候選可在判讀結果按「Agent 補齊02交接／重新檢查並補齊交接」。仍由頂端模型設定決定模型，不呼叫其他案件腳本。

1. 結構／地板：補原圖有來源的漏件，保留已確認地板；未確認外框沿既有Q核對，不新增重複Q。
2. 用途區域：補通道、外推區需求等能定位內容，不新建原圖不存在的隔間。
3. 門窗：將洞口ID、門型、鉸鏈端及使用側明確交接；未知款式不假裝已確認。原生門楣牆帶可位於門洞正上方，不為滿足切牆檢查向下補牆。
4. 設備：原家具群組保留，廚具等增加來源可定位的功能子項；子項超出宿主範圍或沒有原幾何佐證會阻擋。
5. 圖樣：已辨識燈具／裝飾／設備依原圖位置轉為概念占位，原圖文字需求不能冒充實際燈位。燈具分配至02光源，預設停用，亮度／光色留02。
6. 原文要求：需求記錄必須引用來源並綁定物件、功能子項或區域；明確天花、保留、封板、材質、收納等要求不能只作略過註解。02的群組設計prompt及場景intake_handoff保留這些要求。
7. 尺寸／實際模型：逐筆尺寸記錄matched、reference或unresolved；matched須核對端點。未指定高度保留concept來源，不當已確認尺寸；實際GLB／BLEND經既有物件與空間對照檢查。

新增Roomweaver內部handoff欄位，沿現有SemanticProposal／平面修訂／Scene傳遞，不是歷史A.out/B.out的新替代格式。Actor只能新增來源可核對項及更新燈具安裝分類；既有幾何、家具、已確認數字不被重寫。失敗原因逐次保存handoff-pass-*.json／handoff-review.json，執行完成不等於交接成功；失敗會阻擋採用。局部M批次保留已有handoff，區域標記的新增不會清空原已解釋的實物來源紀錄。

「預覽概念3D（未採用）」建立private preview-plan.json及GLB、BLEND、物件對照，使用與正式建模相同的check_plan、Blender及02顯示元件；正式平面、設計revision、Q確認保持。僅這個私人快照可顯示尚待人工確認的地板，不能透過正式import/adopt採用；專案恢復也排除私人預覽工作。其餘幾何／來源錯誤仍阻擋預覽。重開可恢復預覽工作；失敗重試保留舊模型及日誌，不覆寫原件。正式交接仍須人工採用候選、逐項核對及建立正式模型。

本功能沒有完成精細材質、燈光設計或施工驗收；概念預覽不代替03試渲染。共用實作plan_handoff.py、plan_semantics.py、plan_import.py、service.py；UI PlanHandoff.tsx；合成回歸test_plan_handoff.py、test_semantic_batch_scope.py及test_project_library.py。
