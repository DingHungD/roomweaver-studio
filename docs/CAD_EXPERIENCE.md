# CAD修正經驗庫

此功能在01核對平面的右欄「經驗庫」中使用。適用新DWG／DXF案件；不是模型訓練，也不會採用設計、修改原件或替換已確認尺寸。

## 整理、核對與確認

1. 批次修正完成時，成功且通過逐項預覽檢查的M項會自動整理為待確認經驗卡，右欄「經驗庫」清單自動更新，不自動展開詳細資料。每張卡保留本次M草稿、判讀版本、原圖局部及修正結果；只處理本次勾選項，不採用設計、不入庫。待確認／失敗或沒有圖上位置的項目不生成卡，逐項記錄原因；整理失敗時保留修正預覽並顯示原因，可手動重試整理。重複執行同版整理不增加卡，也不覆寫已編輯的卡。
   在圖面選取物件，仍可按「整理選取物件為經驗」；也可從修正頁已完成的M項手動整理。M項須有同版成功回報及圖上範圍。
2. 系統從原圖裁出局部圖片，盤點原生幾何、附近註解，預填判讀及理由。能追溯同案歷史誤判時一併帶入；預填內容仍待你確認。
3. 可修改正確判讀、原本誤判、理由、適用條件及例外。按「保存經驗草稿」只保存本案版本，重開仍在；未確認內容不能被任何案件檢索。切換草稿前先保存編輯；離開專案沿用既有未保存提示。
4. 只有勾選「我已核對此修正正確，允許其他專案參考」，再按「確認正確並加入經驗庫」才發佈。它和「採用判讀草稿」完全分開，不能代替地板Q確認或3D交接。
5. 原圖、平面修訂、目前判讀、目標物件、M草稿或局部圖片變更時拒絕舊確認；需重新整理。已確認內容不原地覆寫。若發現經驗不適當，可「停用此經驗」；停止新案檢索，圖片及歷史仍保留。

舊版批次因全域hash失效而重整時，若M內容、原生來源與成功回報完全相同，沿用原有待確認卡ID及使用者編輯，保存舊修訂後更新到新預覽；不重複生成、不自動確認。已確認案例保持原版本。這種宿主檢查重整不呼叫Agent，範圍與來源規則見PLAN_REVIEW.md。

## 批次整合與使用者授權

修正項清單顯示「是否完成」「是否入庫」兩種狀態。勾選已保存且同版有效完成的M，按「批次進入經驗庫」即明確授權這次所選修正入庫；普通批次修改、整理草稿或顯示完成都不觸發入庫。

Agent讀取所選原生幾何、局部圖與註解，合併相同判讀條件的錯誤；不同問題分開。不以先猜類別強制合併；可合併相符的既有經驗並保留不可變舊版與各來源例子。只允許每個選取ID出現一次；漏項、未選項、重複或過期來源皆拒絕。真正入庫前重驗來源、草稿版本、完成紀錄及圖片；失敗顯示對應M及原因。重開可恢復同批次狀態，不能因刷新重複入庫。

正式庫與待確認草稿先顯示精簡清單，點選才進單項詳細頁；返回前保存未存草稿。正式經驗可比對及停用，未確認草稿仍不供跨案檢索。批次整合保留多個原生描述子與局部圖片作搜尋例子，顯示卡片代表其中一個來源；相似分數不等於判讀正確率。

同一修改項已有當前來源與內容有效的入庫紀錄時，舊私人草稿不重複列為待採用，原草稿及版本仍保留。修改內容改變或經驗停用使有效入庫對應消失時，未確認草稿仍可顯示；物件與修改項的同名ID分開處理。

批次請求與Agent結果保存在本案`semantics/experience-batches/<id>/`。核心`experience_batch.py`沿用既有Agent模型設定；預設gpt-6-sol。正式庫`examples`索引表保存多來源特徵，圖片依雜湊共用，不刪原始經驗。單卡勾選確認流程保持。

## 搜尋依據與時機

`experience_features.py`讀取原生線段、封閉輪廓、弧形及相接關係，建立平移／尺度／直角旋轉可比較的幾何描述子。DXF缺少LibreDWG盤點時，從原生ARC採樣恢復弧角；不是從Agent猜測的語意類別決定。遠處長線裁到查詢局部計算特徵，填色不冒充家具；原始線段不因此修改。

局部圖以旋轉可比的邊緣特徵做粗略圖片比對，原始CAD註解以本機全文索引輔助。這不是神經圖片嵌入，也不宣稱能單靠圖片判斷用途。已確認的正反例再連同原圖交給Agent視覺複核。

SQLite先按原生弧形及幾何複雜度索引取候選，另有不限制弧形的廣泛搜尋與註解通道，不使用Agent猜的門／椅子等類別作排除條件。幾何、圖片、註解共同排序；相關程度不足可回傳0筆，不硬湊答案。相似分數是排序量，**不是正確率**。去重後保留不同解釋，最多5筆；目前最多比較512筆索引候選。相同的確認內容、描述子及圖片只入庫一次，不能靠重複確認增加同一解釋的權重。

初次CAD Agent判讀，以及漏判／檢查失敗的局部複核，才自動查經驗。每階段最多8個局部查詢、5筆參考、3張附圖；重試沿用檢索快照。「比對已確認經驗」可單獨預覽結果與本機耗時，不呼叫Agent。點選、縮放、平移與切頁不搜尋、不呼叫模型。

來源文字、經驗答案、歷史幾何皆是資料而不是指令。歷史案例的座標、尺寸、來源ID及用途不能直接套到新圖；仍需本圖來源綁定、尺寸與連通檢查。若初始候選完全漏掉某圖形，經驗搜尋不會自行使其出現；既有漏判盤點仍需維持。查詢上限與粗略描述子也意味著不能保證找齊所有相似例或杜絕誤判。

## 檔案與責任

- 共用正式庫：**應用程式所選workspace**的`shared/knowledge/cad-experience/`，供登記在此工作區的專案共用。不是某住宅案件的資料夾，不依賴私有開發案例，也不自動上傳GitHub。
- `index.sqlite3`：本機搜尋索引；`entries/<id>/<revision>.json`：已確認案例；`blobs/<sha256>.png`：去重後的局部圖。備份整個資料夾，本版未提供一鍵索引重建UI。停用只新增紀錄及更新索引狀態。
- 本案草稿：`workflows/plan-import/<plan>/semantics/experience-drafts/<id>/`，含局部圖、版本化文字與確認來源。保留來源綁定，不作可清理快取。
- 每次Agent工作：`runs/<task>/experience-search/`及`local-reviews/<round>/experience-search/`保存查詢、實際案例版本、幾何／圖片／註解分數、搜尋及準備耗時、附圖快照與失敗原因。只複製本次有用的少量圖片。

API由`experience_review.py`與`experience_library.py`實作，`experience_retrieval.py`在Agent工作邊界組裝參考；前端`CorrectionExperience.tsx`共用既有原圖及右欄。GET列出草稿及比對；POST整理；PUT保存；POST confirm需要`confirmed:true`及草稿版本；停用需要案例版本。所有寫入沿用本機服務的同源token與版本保護。

## 測試與速度

批次完成紀錄以單項意見及標註快照比對；新增其他修正項、或只處理其他區域，不會使未變更的成功修正失效。尚未確認的舊卡片，僅在最新預覽保留同一成功結果、相同來源及相同修正內容時可確認；重新判讀、改寫該項或失敗重試仍會阻擋舊卡。保存草稿、顯示已完成或整理卡片都不等於確認入庫。

`tests/test_cad_experience.py`使用全新合成CAD及獨立暫存工作區，檢查確認門檻、保存／重開、版本／圖片變更、跨圖旋轉與單位、錯誤Agent類別不影響檢索、正反例、弱匹配拒絕、去重、停用、HTTP授權及不採用設計。

性能應分別記錄：CAD讀取／裁圖、SQLite搜尋／排序、雲端Agent判讀及整個專案開啟；不能把搜尋數十毫秒當成Agent工作或專案載入時間。壓力測試可用獨立的1,000／10,000筆合成索引，不得將測試用模擬確認混入正式庫。實際案件未經使用者確認時只做待確認卡，不能為了演示跨案學習先替使用者入庫。


## 牆交接與柱體經驗

使用者明確指認並要求入庫的M項，經同版逐標註檢查後可依其授權確認，與採用設計分開。正確判讀、適用條件及例外須區分「使用者指認的柱體」與程式推導的輪廓，不能把自動估計高度冒充確認尺寸。經驗內容提醒：牆端／交接處需核對獨立閉合輪廓和厚度突變；等厚T／L接續、櫃體、管道井與加厚牆均為必要反例，不可只靠方形或粗線判柱。
