# 02 編輯：大型模型效能

所有者：Roomweaver 共用編輯器。這是瀏覽器預覽與查詢最佳化，不變更匯入來源、工作模型、設計修訂或 Blender 出圖品質。

## 原因與目前處理

SketchUp 元件數不是瀏覽器繪圖網格數。一個元件具有多種材質時，GLTFLoader 會建立多個材質分片；重複放置元件又會增加網格物件。大型測試模型 的 11,809 個模型物件在 Three.js 中成為 171,182 個網格，實例展開後為 5,750,061 個三角面。2D 柔光還有四方向陰影，會放大繪圖提交開銷。

目前對至少 2,000 網格的靜態模型啟用 `staticPreview.ts`：

- 相同幾何、材質及渲染旗標的重複網格使用顯示用 InstancedMesh；來源物件仍負責選取、材質與保存，不將實例資料寫回來源。
- 鏡射使用獨立的顯示幾何、反轉面序與切線手性；剪切使用完整仿射法線處理。來源座標、頂點、面數與貼圖保持。
- 透明／透射表面獨立顯示，維持排序；動畫、骨架、既有 GPU 實例及線／點模型沿用原顯示路徑。
- 選取先測試分組包圍盒，再以原始三角面求交；移動只同步當前分組。材質更新按物件與共用材質快取，避免重複觸發著色器更新。
- 離開模型時，共用幾何、材質與貼圖只釋放一次。配置清單先建立物件索引，保留原物件順序、分類與來源。

大型批次預覽使用完整場景渲染，避免舊 2D 畫面分層快取與顯示批次互相干擾；小模型繼續使用既有分層快取。陰影、貼圖尺寸與模型精度均未降低。

## 本機驗證與限制

2026-10-25，以 大型測試模型 固定匯入模型與修訂執行離線 CPU 測試：

| 項目 | 原方式 | 最佳化 |
| --- | ---: | ---: |
| 預覽繪圖網格數 | 171,182 | 2,361（少 98.6%） |
| 同次射線選取中位耗時 | 61.13 ms | 4.46 ms |
| 單一分組移動同步 | 未量測 | 0.21 ms |
| Python 配置清單計算 | 1.226 s | 0.089 s |

配置清單的輸出 SHA 完全相同。原始／工作檔沒有重建；來源幾何仍為 575 萬三角面，沒有以減面換取上述數字。

以上不是 GPU FPS。Node 基準使用真正的幾何與編輯程式，但不解碼貼圖、不建立 WebGL；繪圖網格數也不是包含裁切／陰影後的實際 draw calls。測試時瀏覽器工具沒有可用連線，尚未完成新批次路徑的實機畫面／FPS 驗證。證據位於私人 `artifacts/editor-performance-20261025/`，不得發布為公共範例或 fixture。

測試涵蓋鏡射／剪切座標與法線方向、面序、切線手性、透明排序路徑、材質／顏色變更、隱藏與移動、概念元件新增／移除、原網格求交及共用資源釋放；相關既有 2D、陰影、鏡位與材質測試亦須通過。

## 重播與生效

Python 與前端有更新時，重新啟動服務並建置前端。已有頁面先保存修改，再重新整理；不需重新匯入或重新轉 SKP。

```powershell
npm run build --prefix frontend
node tools/benchmark_editor.mjs "path/to/model.glb" "path/to/studio-revision.json" "artifacts/editor-benchmark/run.json"
```

CPU 基準輸入為同版 GLB 與包含 `scene` 的 Studio 修訂；報告會列出限制及取樣耗時。網址加 `?performance=1` 可在畫布 `data-performance` 記錄實際瀏覽器 CPU／下一幀耗時、呼叫與三角數，`data-preview-batches` 記錄顯示批次統計；這些資料只在本機，不發送遙測。

若特定 GPU 出現顯示相容問題，可用 `?preview-batching=off` 暫時沿用原預覽路徑，供同模型 A/B 核對。這不變更模型或設計狀態。
