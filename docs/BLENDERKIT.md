# 單物件的 BlenderKit 配對與替換

入口：**02 編輯 → 材質 → 選取單物件 → 3D 單物件展示 → BlenderKit 家具與材質**。

### 材質詳細編輯的便籤分頁

材質頁的物件名稱固定在詳細編輯上方。2D／整體 3D 畫面分為「主畫面、其他物件、配置範圍」：主畫面顯示模型本身寬／深／高（cm）、歸屬空間，提供移動、旋轉、刪除與「編輯模型與材質」；其他物件提供搜尋、選取、顯示已刪除物件與收合的群組合併。配置範圍提供 2D 框選允許移動區、最多平移距離與通道／門口保留區；精確座標預設收合。模型尺寸為座標軸下的唯讀外框，不因平移／水平旋轉改變，不直接縮放模型；已確認尺寸與替換目標統一在單物件「AI 設置 → 配對限制」。

3D 單物件展示分為「主畫面、材質、AI 設置、候選清單」。主畫面保留來源網址與原件／概念／已套用素材的真實來源資訊；沒有來源證據時不推測為 AI 或網路素材。「材質」頁保留子物件名稱、描述、參考網址、外觀預設、基本色、粗糙度，並收合原本的修復入口為「預覽異常處理」；已有失敗或待採用修正時會展開。點選子物件自動切到材質頁。「AI 設置」統一放用途、尺寸依據、搜尋及原本的基本色／粗糙度建議；模型與貼圖搜尋仍分別選擇目標。候選頁保留配對卡片及收合的歷次使用來源，成功搜尋或連結查核後切到候選頁。空間名稱及全案概念疑點從材質頁工具列「專案管理」開啟；修改後仍需保存草稿。

AI 設置的風格 prompt 與一鍵配置的個別補充共用 `groups[].style_prompt`，修改任一處都同步，保存、重開及復原使用同一份場景修訂。`null`／未提供時相容舊批次個別補充與新增物件的 `design_prompt`；明確清空保存為空字串，不會在重開時被舊描述補回。全局風格、圖片、勾選範圍、保留原件與材質策略仍維持既有意義。一鍵配置按「確認」會先保存尚未保存的場景風格及編輯，再進入物件配置，避免新文字使版本檢查停在無法開始的狀態。

候選、授權確認、替換結果與停止／續跑操作保持原工作流；分頁切換不重建配對元件，不遺失已找到的候選或進行中的修正。只改風格不使舊候選的幾何檢查失效；位置、用途與尺寸的既有防錯不放寬。輸入風格不重新載入物件縮圖模型。這組分頁只套用材質頁，門、裝飾物與光源維持原介面。

前端會讀取本機既有 OpenAPI 格式，確認目前執行的服務接受新風格欄位。若只建置前端而未重啟舊後端，風格欄位暫時停用並提示重啟；其他編輯仍可使用，避免保存時送出舊服務不認得的欄位。重啟後會重新檢查並啟用。

1. 配對整個家具，或先點選子物件再選「子物件材質」。補充用途、風格或尺寸；按「Agent 自動找素材」會先保存現有修改。
2. 沿用「Agent 設定」選擇的本機 Codex 模型。Agent 產生搜尋詞，應用查詢 BlenderKit，再由 Agent 比較實際查得的候選。只傳該物件名稱、組成、尺寸及描述；不傳整案模型，也不宣稱完成視覺相似度辨識。
3. **免費優先，付費僅作候補**。每張卡片保留來源網址、作者、授權、尺寸、配對理由與疑點。免費不等於 CC0；授權以來源頁為準。找不到適合素材就明示，不能由模型捏造連結。
4. 「保存為參考」只把網址與素材識別寫入此單物件／子物件的修訂。選擇「替換」並確認授權後，才下載與建模。付費素材另須明確選取及帳號已有權限，不自動購買。
5. 完成後按「套用替換結果並檢視」。單物件展示保留**已套用來源網址**。模型保留原位置、底部高度與單物件 ID，採等比例縮放至原占位範圍，可指定朝向；不把家具拉伸成完全相同的外框。材質只改指定子物件。
6. 核對 2D、3D、位置與材質後，再重新確認編輯並出圖。全部家具確認後才清理被取代的替換模型與下載暫存，歷次來源連結仍可查詢。已清理的模型無法直接還原，需重新配對下載；原始匯入與既有渲染成果保留。

## 一鍵配置與風格

入口：**02 編輯 → 材質 → 一鍵配置**，不必先進入單物件展示。

1. 預設整屋、全部類型、全部物件勾選，不沿用上次取消勾選的範圍；提供「整屋全部選取」及全案／已選／未選計數；可改為指定空間及家具類型。空間依物件已保存的歸屬篩選，不根據相機眼位猜房間；未分區的物件仍列在整屋。
2. 共用風格接受文字與一張 PNG／JPG 參考圖，可全局關閉。展開「核對物件與個別風格」可取消特定物件、修正推定類型、取消沿用共用風格、另加文字及圖片。個別補充與共用描述共同送出；取消沿用後只送該物件資料。
3. 類型目前依概念家具類別、父物件及子物件名稱推定，未知列「其他」，不是圖像分類。牆壁合為一組、地板合為一組，每件家具保持獨立。牆壁／地板／門窗／天花每組只搜尋一次材質，不替換其幾何；選定空間時只套用該空間的子元件。雙擊單物件仍可選一段牆或一塊地板單獨配對。送出前顯示物件數與實際目標數；每次最多 100 個目標，大案可按空間分批。
4. 圖片限 5 MB／2500 萬像素，清除中繼資料並縮至最長邊 1600 px；只供風格判讀，不作尺寸或商品真偽證據。需要支援圖片的 Codex 模型；所選描述、圖片與目標資料會送至該 Agent，使用相應額度。
5. 按「一鍵下載並配置第一版」即開始搜尋及自動下載套用：使用 Agent 排序後第一個合適的免費 CC0／Royalty Free 候選。下載前仍核對版本、價格、授權及大小。不自動購買、不自動使用付費候選。
6. 沒有免費候選時，保留用途與尺寸、放寬風格重新搜尋一次；下载／建模失敗則逐一嘗試其餘免費候選。每個目標都有狀態；查無素材、登入失效或全部失敗會保留原件與原因，不能宣稱全部成功。覆蓋所有選取目標不代表素材庫一定存在合適家具。
7. 三階段為「範圍與風格 → 第一版與備選 → 確認家具與清理」。結果可點「預覽／選擇備選」進入單物件展示。備選只保存來源連結及中繼資料，使用者選定後才下載。同清單在該物件替換後繼續有效；不允許套用到其他物件或非祖先模型。
8. 自動套用使用既有單一 Blender 佇列。進度保存於 `batches/<id>/placement.json`，每次工作有固定去重識別碼。重啟後按「核對既有工作並繼續」，先核對已完成工作，不重送下載。尚未完成的 Agent 搜尋中斷後不自動重跑雲端搜尋，可重新配置。
9. 若使用者另行修改設計，自動套用暂停並保留結果；不覆蓋新修訂。UI 有未保存修改時不自動載入新模型。停止後不繼續套用，執行中的 Blender 工作仍可能完成。

## 手動框選新增家具與裝飾物

02 編輯分為 **材質、裝飾物、光源、觀看點**。材質頁保留整屋家具「一鍵配置」；裝飾物頁只操作裝飾物，背景家具供定位。裝飾物操作列依序為「一鍵配置裝飾物、框選新增裝飾物、復原上一步」；光源頁對應「一鍵配置照明、新增光源、復原上一步」。一鍵按鈕會展開建議區、保存配置並接續 Agent 免費素材配對／下載；逐項結果直接列出。收合後仍在背景執行，不清理舊模型。

若要先調整空間、風格或天花高度，展開「自動建議裝飾／照明配置 → 配置範圍與風格」；「只預覽」不套用場景或下載。手動新增光源放在畫面平面中心、高度 2.5m，選中後於右側調整；它是獨立光源，不會自動下載燈具。

1. 在材質或裝飾物頁按「框選新增家具元件／裝飾物」，在 2D 拖出矩形範圍。右側確認名稱、類型、尺寸、所屬空間；範圍中心落在可見桌面等表面時，帶入其高度，仍可手動調整底部高度。
2. 選擇建立方式：輸入需求請 Agent 找模型、貼上 BlenderKit 單一模型頁連結，或先加入概念占位。新增後會保存修訂；搜尋／連結查核失敗也會保留占位，可在單物件展示重試。
3. 模型連結查核不呼叫 Agent；只接受官方 HTTPS `asset-gallery-detail/<UUID>/` 模型頁，不接受任意下載網址。顯示實際候選與授權後，沿用「選擇並替換 → 下載 → 套用」流程，付費模型不自動購買。
4. 新增元件可選取、平移、水平旋轉、刪除及復原未保存的上一步；已套用來源網址與新增需求保存於修訂。裝飾物替換模型後仍保留分類，不因素材名稱改變而離開該頁。

框選是占位範圍，不是精細碰撞或動線驗收；支撐高度使用可見幾何射線，透明物件、遮蔽與不規則表面需人工核對。家具先以通用類型建占位，最終素材保持比例，不保證填滿矩形。手動新增與替換不觸發舊模型清理。

## 儲存空間

- 採用第一版／備選時**不立即刪檔**。逐件檢視後按「所有家具已確認，清理未使用模型」。尚未成功替換的目標，必須逐項勾選保留原件，不能默默略過。
- 確認綁定當前修訂；之後再修改或替換，確認失效。案件仍有排隊／執行工作時暫緩清理。
- 清理目前版本的下载暫存、已被取代的 replacement 祖先版本，以及本批次失敗／未採用的替換工作大檔。保留目前 GLB／BLEND、原始匯入、照明來源、修訂 JSON、所有候選連結、授權及雜湊；不清除其他批次尚未採用的獨立工作。
- 最新 BLEND 移除不再使用的網格、材質及貼圖 datablock。已清理的舊模型標記不可再直接還原／出圖，但仍可從備選重新下載。
- 清理不是整案垃圾回收；既有渲染圖片與其他入口工作檔不在此範圍。

## 室內外照明與生活裝飾

- **02 編輯 → 光源 → 自動配置照明：預覽燈位**：依已命名地板的實際範圍安排天花燈位，指定距地板的天花高度，可勾選沙發旁落地燈。採用後新增天空環境、室外 SUN 日光與綁定燈具的室內光源。燈具模型由同一個 BlenderKit 批次搜尋、免費優先下載，不假設模型自帶可用光源。原有光源保留，避免覆蓋已調整設定。
- **02 編輯 → 裝飾物 → 自動建議裝飾配置 → 預覽裝飾位置**：依物件名稱／用途和可用範圍，為餐桌、書桌、茶几、床頭、爐台、水槽、洗手檯和沙發區安排花瓶、書籍、鍋具、餐具、洗手用品或地毯。只採用有支撐與可用空間的候選；可逐件取消。不會把未知家具名稱猜成可用檯面。
- **套用位置並自動找免費模型**：先保存概念占位與燈位，再沿用正常 Agent 配對與 Blender 替換佇列。每件結果、失敗理由、來源與備選可查。只有確實採用到場景才計入已替換；無合適候選保留概念占位，不假裝完成。
- **只重試未完成項目**：從當前修訂重新配對失敗項目，成功物件不重送。暫時容量不足或逾時最多嘗試三次；無免費結果再保留機能、放寬風格一次。不是無限重試。
- 燈具移動與旋轉會同步其光源。薄型吸頂燈以頂部貼齊設定天花，光源保持在底部之外。新增裝飾尺寸是可用範圍；既有家具仍保留功能高度保護，避免把餐桌縮成茶几。
- 匯入分散組件可在材質頁使用 **合併成單物件**。只合併原始模型且變換一致的組件，保存網格 ID 與光源綁定；不暗中改變家具位置。已替換素材與概念家具不能用此入口合併。
- 全部操作從 UI 呼叫共用服務，沒有案件 ID 或固定住宅座標。**配置位置目前是幾何規則，不是 Agent 看完整空間進行設計**；Agent 負責查詢與比較素材。名稱、空間歸屬、模型品質、可用素材與服務狀態會影響結果。
- 高度為使用者設定，非自動偵測天花。室外光是示意日光＋環境，尚無 HDRI 自動下載或基地日照分析；有無真正窗戶開口仍影響入室光。檯面使用包圍盒，未做精細碰撞／動線驗收。套用後請核對 2D／3D，再做低解析試圖。
- 不自動按下最終確認，也不清理任何歷史工作或下載；確認前可比較原版與備選。

設定保存在案件 `workflows/interior-studio/staging/<id>/`，記錄提案、採用修訂及批次。`POST .../staging` 預覽，`GET .../staging/current?kind=lighting|decor` 續開，`POST .../staging/{id}/apply` 採用，`POST .../staging/{id}/retry` 重試失敗項目。測試使用 `tests/fixtures/staging/` 合成模型，不打包真實案件。

## 平移與旋轉操作

在 2D／3D 選取家具，按「移動／旋轉」，切換平移或水平旋轉。可拖曳旋轉環、輸入角度或按 ±90°。旋轉以單物件中心為基準，家具保持直立；綁定光源的位置及方向同步旋轉。變更保存於修訂 JSON，網頁預覽及 Blender 出圖共同套用，原始 GLB／BLEND 不原地改寫。

## 帳號與限制

- 配對需要本機 Codex 的 ChatGPT 登入。搜尋與公開免費素材可不提供 BlenderKit key；若來源要求登入，設定自己的 `BLENDERKIT_API_KEY` 環境變數並重新啟動服務。不要把 key 放進案件、前端或 Git；應用不讀取 Blender 外掛的私人登入資料。
- 限 BlenderKit 官方素材服務，下載前重新核對版本、免費狀態與授權。價格或版本改變時要求重新配對；HTTP 錯誤、權限不足、缺貼圖或模型不相容均保留原場景。
- 單檔上限 150 MB、最多 500 個素材網格。材質資產必須能唯一辨認要套用的材質。只有 BlenderKit 的 `model`／`material` 可用；場景、HDRI、外掛或任意網址不是此入口。
- 有官方 2K 貼圖版本時優先下載該 Blender 套件，否則取原檔；下載雜湊與實際解析度版本另存來源紀錄。這可避免僅試用材質就下載大型 8K 原件。
- 保留原生 Blender 材質節點；GLB 只保留可匯出的 PBR 表現。程序材質、特殊節點及部分貼圖座標可能與 Cycles 不同；目前沒有自動完整烘焙。這是素材替換，不是寫實品質或動線驗收。
- 下載與建模沿用單一重型工作佇列；關頁後工作仍可查詢。編輯期間若版本變動，完成的替換不會覆蓋新設計。服務中斷不自動重新下載或提交高成本工作。

## 資料歸屬與整合

- 候選與來源：案件 `workflows/interior-studio/asset-matching/`。
- 每次替換：案件 `runs/interior-studio/<job-id>/`，含雜湊、來源、交接檢查及待採用場景；現用 GLB／BLEND 隨案件 runs 備份，不塞進 SQLite。清理後舊版本只留紀錄。
- 設計採用仍由不可變修訂 JSON 管理。新模型保留其他物件的 ID 與修訂操作，燈具綁定沿用原單物件 ID。
- 共用實作：`studio/asset_matching.py` 管理任務、過期檢查與採用；`asset_batch.py` 管理範圍、圖片及依序配對；`asset_automation.py` 管理可恢復的自動套用與最終確認；`asset_storage.py` 管理來源歷史與安全清理；`blenderkit_client.py` 查詢及有界下載；`visualization/asset_blender.py` 處理新模型；前端 `AssetMatcher.tsx`／`AssetBatch.tsx`。
- `POST /api/studio/projects/{project}/asset-links` 查核指定模型連結，回傳同格式候選與可重試的操作識別。只從官方 catalog 取得來源與下載資訊，不使用使用者網址下載檔案。
- `POST /api/studio/projects/{project}/asset-matches` 建立配對；`GET .../asset-matches/current?group_id=...` 續開。候選 `/reference` 保存來源，`/replace` 提交工作；`asset-replacements/{job}/adopt` 採用，`asset-replacements/restore` 受控還原。

## 共通匯入分組標準

圖片／DXF 建模及 GLB 匯入都經過相同的交接分組：

- 牆壁一個父群組、地板一個父群組；原本 mesh、studio_id、房間歸屬及材質留在子元件。不是熔接網格，也不會填掉門窗開口。
- 同一件家具的組成依來源 assembly_id／source_id、命名前綴或模型階層歸組；不同家具實例分開，即使共用來源 ID。不要把所有 chair 共用一個無階層區別的 assembly_id。
- 圖片／DXF 的用途角色會寫入 GLB 的 studio_role。外部 GLB 優先讀此語意，其次讀明確的牆／地板名稱；排除落地燈、壁燈、壁櫃等。沒有用途、階層與命名線索的任意 GLB 不能可靠自動分類，請先命名或在編輯介面合併，不按距離盲目合併家具。
- 整屋材質批次每群組一筆候選、一個下載替換工作；所有目標子元件共用同一材質，備選連結可再次套用同一範圍。空間篩選綁定當次子元件清單，不能染到其他房間。
- 舊案在「材質 → 一鍵配置」使用「整理牆地分組」，建立新修訂，保留原圖、BLEND、GLB、舊修訂及子元件材質。進行中的配置需先停止。位移／旋轉不同或含不同模型替換來源時明示原因，不強行合併而改變設計。
- 自動照明與裝飾仍使用子元件幾何判斷支撐及碰撞，不把整屋牆群組的包圍盒當成一整塊實牆。

驗證：`tests/test_structural_groups.py`、資產批次／採用測試及 `tests/integration/test_asset_replacement.py`（真实 Blender，整組套用後再單獨修改一段，核對其他物件不變）。


## 用途防錯、尺寸來源與牆地 UV（本機待驗收）

這是所有專案共用的 UI → API → 佇列流程，不依賴任何案件腳本。

- **02 編輯 → 材質 → 選取物件 → 配對限制**：記錄必要用途、尺寸來源及來源說明。已確認／可用範圍需填三軸公尺與來源；未知不自動降格成概念估計。規格寫入不可變修訂的 `groups[].asset_requirements`。一般概念家具可以推定估計；舊匯入沒有可靠資料就保留未知。
- 用途從穩定父物件名稱或明確規格取得，不從已替換模型的子物件名稱反推。候選名稱與 Agent 疑點共同檢查；洗碗機、洗衣機、爐具、衣櫃、書櫃等不能互換。未知用途列待核對。這是保守分類與規則檢查，尚非對任意商品圖片的完整語意保證。
- **一鍵配置**自動跳過用途不符候選，保留其網址及原因。每個目標一輪最多實際嘗試三個合格免費候選；「只重新搜尋待處理物件」可建立新批次，成功物件不重送。下載、尺寸、UV 或貼圖探針失敗會改試下一個。付費候選不自動採用。來源未知仍沿用嚴格適配；估計／範圍僅放寬高度占比，不超出可用外框、不拉伸。已確認三軸尺寸容差 2%（最低 2 mm），不改寫確認數字。
- **配置工作流**：自動檢查候選用途與貼圖，修復牆地座標及檢查舊用途。無合格備選時，已知錯配的舊家具透過新工作副本局部回復原件，保留其他群組、位置、必要家具與候選。來源已清理／不在來源鏈中時會停止並回報，不猜造原件。
- 缺失／退化 UV 以世界公尺沿主要面向投影，鄰接地板共用方向與尺度；有效既有 UV 保留。材質工作會檢查匯出 GLB 實際引用的 TEXCOORD。新平面建模的牆地也在建立時補 UV。
- 牆地預覽材質由 Cycles 計算一公尺、512px 的無照明基色樣本，檢查非空、非全黑與有限數值，再生成 GLB 貼圖。原生 BLEND 保留原節點，最終渲染不使用這張近似貼圖。後續換其他家具仍保留該預覽，不重回程序節點匯出黑色。預覽使用簡化粗糙度；大型非重複材質、複雜位移或特定物件座標節點仍需人工判圖。
- 操作不清理歷史模型，也不自動確認設計。報告分開記錄用途阻擋、尺寸來源、UV 修復、探針數值及實際 GLB 檢查；技術通過不等於最終設計驗收。

共用模組：`studio/asset_quality.py`、`visualization/asset_fit.py`、`visualization/surface_uv.py`；測試：`tests/test_asset_quality.py`、`tests/test_asset_automation.py`、`tests/integration/test_surface_uv.py`、`tests/integration/test_asset_replacement.py`。整合測試使用合成場景與公開範例素材，不呼叫 Agent。


## 第二批：原因導向修正、局部避碰與材質預覽

所有入口共用同一服務，新專案不依賴 Project03／04 腳本。

- 新的「一鍵配置」在候選用完後帶著實際失敗原因重新搜尋，最多 **2 輪重新搜尋、每輪試套 3 個不同合格免費候選**。原清單與每輪候補連結保留；用途不明、登入／環境失敗不盲目重搜。新的批次自動執行上述修正，成功物件不在同一批次重做。舊記錄仍保留原原因。
- 失敗回饋區分用途、尺寸、碰撞、材質與執行環境，搜尋端排除已失敗素材 ID。搜尋任務與操作鍵持久化；雙擊、程序重啟不重複建立已登記的工作。服務重啟中斷的 Agent 任務明示狀態，不偷偷切換模型或再次消耗額度。
- 模型自動替換在工作副本量測幾何，按目前修訂的旋轉／平移檢查其他元件外框。超過 5 mm 的三軸穿插會攔截；接觸地板等支撐面可保留。檢查採各網格外框，對凹形／交錯家具可能過於保守，並非三角形精密碰撞或完整動線驗收。
- **02 編輯 → 選取物件 → 配對限制 → 局部避碰**：可在 2D 框選允許移動區域與門／通道保留區，核對右側座標並設定最多平移距離（0–0.5 m）。預設 0，不移動；只在明確區域內以 5 cm 步距找最近安全位置，不改高度、已確認尺寸、固定牆或其他家具。沒有安全位置就換候選／保留原件。門扇弧線與動線不由外框檢查自動推定，應用保留區表達。
- 單物件中的 **材質預覽修正（本機） → 修正目前材質預覽**：不使用 Agent、不下載，建立新 GLB／BLEND 副本；完成後按「採用預覽修正」。補 UV 並以 Cycles 烘焙不含場景照明的 512px 色彩、粗糙度、金屬度及切線法線的一公尺樣本。原生節點、其他物件、素材連結及舊模型保留；新增版本會使舊渲染過期。
- 新材質替換也共用上述預覽處理。透明／玻璃保留原生匯出，不以不透明色塊覆蓋；無法可靠辨識的複合表面節點會停止並說明。其他原有 PBR 常數通道保留；位移、非重複／物件專用座標仍有 glTF 相容限制，不能當成完整多通道烘焙器。
- UI 區分「依原因重新搜尋」「下載與替換中」「需要處理」，成功結果顯示位移量及預覽修正摘要。配置與修正不自動清理任何歷史模型；仍須使用者另按最終確認清理。

主要實作：`studio/asset_repair.py`、`studio/asset_automation.py`、`visualization/asset_placement.py`、`visualization/asset_collision.py`、`visualization/surface_uv.py`。測試見 `test_asset_repair.py` 與三項 `integration/test_asset_*`／`test_surface_uv.py`；實案證據僅留本機 artifacts。

## 三階段配置彈窗

入口：02 編輯 → 材質 → 一鍵配置。三個分頁共用同一份設定，切換分頁、關閉彈窗去主畫面查看物件後再開啟，不清掉未提交設定。重新整理瀏覽器仍以已保存修訂及 Agent 任務為準。

1. **範圍與風格**：預設全屋，可依空間／家具類型篩選。啟用全局風格但留白時，API 與 UI 同樣使用「溫暖北歐，淺橡木與米白布料，保留輕盈感」。提供三個短風格預設、文字／圖片參考與可收合的個別設定。按確認只進入物件配置，不下載。
2. **物件配置**：自動帶入名稱、圖面區域、尺寸來源與使用側建議；Agent 可整理選取範圍的用途、方向與風格。尺寸唯讀，不以建模外框冒充確認標註。多選疑點篩選採聯集並顯示計數。用途不明阻擋開始，除非勾選本次保留原件；方向不明不阻擋。保留項目不搜尋、不下載、不替換。按開始配置先保存規格成新修訂，再送出批次。
3. **輸出結果**：顯示搜尋、候選、失敗原因、替換與概念模型來源。候選試套失敗自動改試並最多重搜兩輪；原來兩個手動修正按鈕移入工作流。中斷／停止的批次保留繼續入口，不自動重啟雲端任務。最終確認清理按鈕僅在此分頁；清理前保留舊模型與全部備選連結。

### 位置、外觀與效能

個別風格與規格卡片共用目前模型縮圖及平面位置圖。平面位置是各群組外框示意、橘色為目標，不是新渲染的設計圖。使用一個延遲建立的 WebGL renderer、同一模型載入與依修訂的圖片快取；卡片進入可見範圍才產圖，沒有持續動畫或每卡一個 WebGL 畫布。主畫面查看不提交、不改模型。

### 使用側與 Agent 邊界

- 櫃子／抽屜是門片、抽屜及取物侧；桌子區分一般多側桌面與書桌膝部空間；椅子是椅背相反側；沙發是坐墊前緣；床頭與上下床側分開核對。牆地不要求使用側。
- 已確認用途、尺寸和使用者方向優先；名稱不明不單靠大小猜用途。靠牆與空隙只作建議，不能證明櫃門、椅背或使用通道。Agent 可退回不確定或多側，不以無幾何依據的方向覆蓋使用者設定。
- 當前整理用同一個 Agent 讀取選定範圍及共用需求，保持全案理解一致；實際素材搜尋使用至多兩個獨立 Codex 工作槽。停止會中斷兩個執行器；下載／Blender 工作仍使用既有單工作佇列，採用序列化，不同工作不並寫同一 BLEND。
- 沒有多視角模型語意辨識的物件，仍需使用者核對；方向待確認不能顯示已通過。材質策略可指定全案、沿用原模型、指定部位。後兩者尚未具備安全的跨模型部位轉移，因此自動替換保留原件與候選，明示原因。

### Agent 概念家具與錯誤修正

新批次的「開始配置」預設包含：免費候選 → 試套檢查 → 無可用候選時 Agent 設計概念家具 → Blender 建立與檢查 → 依錯誤修正版。已完成的舊批次可從輸出結果按「Agent 補建未配置家具」，只處理未配置的支援家具；不重做成功或明示保留原件的項目。這是同一套 UI／API 工作流，沒有案件專用腳本。

支援 21 種用途：桌、書桌、椅子、沙發、床、上下舖、收納櫃、書櫃、衣櫃、鞋櫃、床頭櫃、梳妝台、電視、洗衣機、洗碗機、冰箱、爐具、水槽、浴櫃、馬桶、淋浴。用途必須已知且採全案材質策略；不明用途、保留原材質或指定部位轉移尚未驗證時，維持原件。牆地仍走群組材質配對，不改成生成家具。

Agent 回傳有界設計資料（層板、門片、抽屜、座位、配色及修正說明），共用建模器保留必要結構，例如上下舖的兩床、護欄及梯子。不執行 Agent 生成的 Python。模型標為 `agent_parametric`／`concept`，採程序材質與簡單倒角；不是 BlenderKit 商品，也不等同精細模型、施工圖或安全驗收。

每件最多三版幾何嘗試。碰撞錯誤附障礙物、相交外框及穿透量，下一版收到前版參數與檢查結果。未確認／估計尺寸允許每側最多 8 cm、且不超過原軸 10% 的內縮；確認尺寸不可內縮、不改牆壁或群組位置、不刪必要機能。生成參數不合法會回傳錯誤給 Agent 修正一次；登入、額度、環境故障不假裝成找不到商品，也不無限重試。明示 Agent 任務失敗可由 UI 再試。

仍使用固定操作識別碼、修訂核對、Blender 佇列、用途／尺寸／碰撞檢查與 GLB／BLEND 交接。只有檢查通過才採用新修訂；三版未通過保留原件與逐版錯誤。完成不代表使用方向已確認，使用者仍須預覽。原件、歷史模型與所有候選連結留到使用者明確確認清理。

資料權威仍是 `groups[].object_specification`、`asset_requirements` 和不可變修訂；生成模型的 `generated_reference` 記錄 Agent 任務、用途、來源與版本。生成配方、碰撞檢查及結果放正常工作 run；Agent 任務由本機工作服務保存。共用核心不依賴指定案件腳本。

驗證：`tests/test_generated_furniture.py` 涵蓋全部用途、必要結構、確認尺寸、格式回修、三版上限與重播去重；`tests/integration/test_parametric_assets.py` 驗證真實 Blender 與來源保全。實案證據留本機 `artifacts/generated-furniture-20261013/`，不作公開 fixture。

### 候選模型的尺寸改造

物件配置卡片新增「候選模型尺寸」：可選桌櫃優先改造，或只等比適配。啟用改造時，桌、書桌、收納櫃、書櫃、衣櫃、鞋櫃、床頭櫃使用現有尺寸規格；原尺寸來源分類不變。沒有確認標註時，圖面區域／原占位僅是近似目標。

先選較接近的水平朝向及等比尺寸，再用有界的分段幾何調整補足三軸尺寸；靠近外緣最多 4 cm 的區段只平移，中央承擔伸展，盡量保留板端與支腳細節。任何軸超過等比基準 50% 就改試候選。任意造型或內部細部不保證完全不變，仍需預覽。材質節點、貼圖與 UV 保留，局部紋理尺度需人工核對；不對椅子、沙發、床、家電任意拉伸。

改造發生在新 BLEND／GLB 工作副本，重新量測、碰撞與交接檢查後才採用。調整數字記在 replacement-report 的 dimension_adjustment；原件、確認尺寸與備選連結保留。已確認尺寸不為避碰縮小；碰撞沒有安全修正空間就保留原件。


## 依家具用途適配尺寸（2026-10-13）

一鍵配置及單物件替換共用同一套適配程式。已確認且有來源的三軸尺寸仍嚴格核對（2%／2 mm 容差）；預覽模型外框不會蓋過確認值。明確的可用範圍是三軸上限，不要求填滿。未知／估計尺寸的水平外框暫作配置參考，高度不再要求達到占位的 80%。已辨識用途的家具優先保留素材原生尺寸與比例，必要時等比縮小至水平範圍；以家具類型的寬鬆整體高度範圍拒絕明顯錯誤尺度。這些範圍是工程保護值，不代表人體工學或設計驗收，座高、檯面高與安裝高度尚未由幾何語意完整辨識。

未知或估計的桌櫃不再強迫伸展以填滿占位；局部伸展只在已確認尺寸且允許改造時啟用。確認數字、用途、使用者的保留原件設定及碰撞檢查不放寬。套用報告顯示參考尺寸、結果尺寸與來源，未知高度差異標示需預覽。候選不合仍沿用既有免費候選、兩輪原因導向搜尋及受限概念模型備援，原件與歷史結果保留。

升級前完成的批次若有尺寸失敗，輸出結果頁提供一次「沿用候選重試尺寸適配」。透過原本的恢復 API 執行；只重試尺寸失敗的模型，不重做成功項目、明示保留項目、材質或純碰撞失敗。舊嘗試寫入歷史，新操作有獨立去重鍵；重複點擊／重啟不再重設重試輪次。新案直接使用新版規則，不需此升級入口。

驗證：`tests/test_purpose_fit.py` 使用合成尺寸與批次，涵蓋未知高度、家具用途差異、確認尺寸、範圍上限與重試去重；真實 Blender 保全與尺寸改造由 `tests/integration/test_parametric_assets.py`、`tests/integration/test_asset_replacement.py` 核對。本機實案證據位於 `artifacts/purpose-fit-20261013/`，不屬於可公開的通用 fixture。

## 指定候選的自動修正

02 編輯 → 材質 → 3D 單物件展示 → 候選清單 →「選擇並替換」：確認下載後，模型走獨立且可恢復的替換流程。第一版啟用用途／尺寸來源適配及碰撞檢查；方向填 0 時可比較水平 0/90 度，非 0 度固定使用者指定方向。原先手動入口缺少自動方向適配，會把狹長衣櫃等縮得過矮，現在已統一。

若尺寸或碰撞失敗，Agent 收到原候選尺寸、限制、前版參數與檢查結果，最多追加兩版修正。只處理同一候選：未確認／估計尺寸可等比縮至適配結果的 80–100%；已有確認尺寸的支援桌櫃可使用既有局部尺寸改造。保留用途、素材身分、材質、必要部件與位置限制。修正後仍檢查用途高度、碰撞與模型交接。不能安全修正就保留原件；不自行換候選、不生成另一款家具來冒充指定模型。

通過後自動保存並採用新修訂，畫面顯示每版錯誤與修正原因。編輯在工作期間變更時停止覆蓋；未保存的前端修改也不自動被新版本覆蓋。工作識別碼去重；重啟後提供「繼續修正」，不默默重啟雲端任務。停止只取消後续決策／採用，已開始的 Blender 工作可能仍會完成。下載／帳號／環境問題明示，沒有自動改用付費模型。

此 Agent 修正入口目前針對家具模型；材質保留既有烘焙、UV、預覽檢查及手動採用流程。舊模型及候選網址仍保留，直到使用者另外確認清理。

實作：`studio/selected_repair.py`、`visualization/asset_blender.py`、`AssetMatcher.tsx`。驗證：`tests/test_selected_repair.py` 與 `tests/integration/test_parametric_assets.py`。本機實案紀錄留 `artifacts/selected-repair-20261013/`。


### 裝飾物的辨識、支撐與看圖循環

裝飾配置沿用既有「一鍵配置」與重試入口。花瓶、書籍、餐具先保存 `groups[].decor_context`（物品用途、承載群組、提案來源）；承載家具名稱不能成為物品用途。原有三類占位在正常重試時由採用提案恢復資料，只修正可追溯的自動誤判，不覆寫人工用途或已確認尺寸。沒有新增位置的預覽不再遮住既有配置結果。

候選先經用途／尺寸／碰撞檢查，Blender 再用承載模型的實際三角面向下探測；在原承載家具附近每軸 8 cm 內尋找支撐，垂直最多探測上下約 10–12 cm，保留尺寸與家具。無支撐則拒絕，不把包圍盒當成檯面。這是局部裝飾放置校正，不是結構或動線驗收。

三類物品在自動採用前產生保留原材質的 512px 單物件與局部承載預覽，交給支援圖片的目前 Codex 模型核對用途、支撐、比例、材質與可見性。工作完成、機器檢查、Agent 看圖與使用者預覽分開記錄。`pass` 才採用；`retry` 的原因進入既有改試候選／最多三版概念生成；`uncertain`、登入或服務故障暫停並保留原件。任務綁定不可變工作 ID 與圖片雜湊，重播不重新付費呼叫同一檢查。

免費候選用盡時，Agent 可決定花瓶／花朵、書本封面／書頁、碗盤的有界概念配色及尺寸內縮；共用建模器建立曲面容器、花朵和書本組成，不執行任意生成程式。這三類與原有 21 類家具共用生成與錯誤修正流程。概念外觀仍不等同商品模型。

裝飾物結果可展開兩張預覽與具體看圖判斷。所有候選連結、未採用工作與舊模型保留，除非使用者另行確認清理。其他家具的視覺複核見下節。

驗證入口：`tests/test_decor_review.py`、`tests/test_staging.py`、`tests/integration/test_decor_pipeline.py`。合成測試使用不同平移／旋轉／高度的家具與缺少支撐的反例；實案紀錄在本機 `artifacts/decor-review-20261013/`，不作公開 fixture。

### 一鍵配置中的家具看圖與修正

所有 `kind=model` 的自動替換（包括概念生成）都在採用前核對實際模型，不依賴案件名稱或專用腳本。牆地群組的材質替換仍走原有 UV／貼圖檢查。家具先通過用途、尺寸、碰撞及實際網格的有限座標／有效面／立體外形檢查，再由 Blender 以原生材質生成三張 512px 圖：相反兩側單物件及實際位置的局部剖視。剖視會略去上方及前方高遮擋物，記錄保留群組與略去部件；不是全屋動線或完整碰撞驗收。

目前選用的 Codex 接收真實圖片、用途、尺寸来源、使用側及機器結果，核對機能結構、比例、材質與放置。圖片不足或判斷不確定會暫停，不能將 Agent 任務完成當作看圖通過。圖片雜湊、模型工作 ID、看圖任務及修正歷史綁定保存；舊模型及免費／付費候選連結保持。

用途定義共用 `model_contract.py`：搜尋與看圖使用 UI 的機能語意。例如 `dresser` 在本工具指梳妝台，需要檯面、膝腿空間及鏡子，不可用抽屜櫃代替；`vanity` 指浴室洗手台。Agent 回報獨立辨識的用途與逐項機能結果，程式先正規化已知同義詞，再核對需求；用途不符或任一必要機能失敗，即使 Agent 回答 `pass` 仍退回修正。沒有完整回報則保留原件，不自行補成通過。

比例、尺寸或碰撞失敗，可對同一免費候選請 Agent 提出一次受控修正：未知／估計尺寸可在自動適配後縮小至 80–100%；已確認尺寸不能縮小；已確認桌櫃可用既有局部尺寸適配。不可移牆、刪必要零件或任意執行 Agent 程式。不安全、無有效變更或再次失敗則改試下一候選。用途、必要機能、材質缺陷則直接改試候選；候選用盡再依既有上限生成／修正概念家具。方向未知只註記待預覽；本輪不宣稱能自動辨識並修正任意商品的開門面。

操作仍為 **材質 → 一鍵配置 → 範圍與風格 → 物件配置 → 開始配置**。輸出結果可展開「實際模型檢查」檢視圖片、判斷與修正原因；不增加修復按鈕。使用者預覽及清理確認仍是分開的動作。

共用程式：`visualization/model_review.py`、`studio/decor_review.py`、`studio/model_repair.py`、`studio/asset_automation.py`。回歸測試：`tests/test_furniture_review.py`；真實 Blender 合成測試：`tests/integration/test_furniture_review.py`，覆蓋椅子、床、書桌、收納櫃及確認尺寸／原件保全。

### 門與光源編輯入口

門配對見 [DOOR_EDITOR.md](DOOR_EDITOR.md)。光源頁選取綁定的室內燈具後，可切到 3D 單物件展示、選燈罩／底座等子物件，使用既有模型與材質配對、候選清單及替換流程。單物件視圖將光源設定收合，仍可調亮度、光色、位置與綁定。室外日光及未綁模型的獨立光源不提供虛假的模型預覽。燈具替換維持同一群組識別與光源綁定，吸頂燈再次替換也須保留頂部安裝位置。
