# 單物件的 BlenderKit 配對與替換

入口：**02 編輯 → 材質 → 選取單物件 → 3D 單物件展示 → BlenderKit 家具與材質**。

1. 配對整個家具，或先點選子物件再選「子物件材質」。補充用途、風格或尺寸；按「Agent 自動找素材」會先保存現有修改。
2. 沿用「Agent 設定」選擇的本機 Codex 模型。Agent 產生搜尋詞，應用查詢 BlenderKit，再由 Agent 比較實際查得的候選。只傳該物件名稱、組成、尺寸及描述；不傳整案模型，也不宣稱完成視覺相似度辨識。
3. **免費優先，付費僅作候補**。每張卡片保留來源網址、作者、授權、尺寸、配對理由與疑點。免費不等於 CC0；授權以來源頁為準。找不到適合素材就明示，不能由模型捏造連結。
4. 「保存為參考」只把網址與素材識別寫入此單物件／子物件的修訂。選擇「替換」並確認授權後，才下載與建模。付費素材另須明確選取及帳號已有權限，不自動購買。
5. 完成後按「套用替換結果並檢視」。單物件展示保留**已套用來源網址**。模型保留原位置、底部高度與單物件 ID，採等比例縮放至原占位範圍，可指定朝向；不把家具拉伸成完全相同的外框。材質只改指定子物件。
6. 核對 2D、3D、位置與材質後，再重新確認編輯並出圖。全部家具確認後才清理被取代的替換模型與下載暫存，歷次來源連結仍可查詢。已清理的模型無法直接還原，需重新配對下載；原始匯入與既有渲染成果保留。

## 一鍵配置與風格

入口：**02 編輯 → 材質 → 一鍵配置**，不必先進入單物件展示。

1. 預設整屋、全部類型、全部物件勾選，不沿用上次取消勾選的範圍；提供「整屋全部選取」及全案／已選／未選計數；可改為指定空間及家具類型。空間依物件已保存的歸屬篩選，不根據相機眼位猜房間；未分區的物件仍列在整屋。
2. 共用風格接受文字與一張 PNG／JPG 參考圖，可全局關閉。展開「核對物件與個別風格」可取消特定物件、修正推定類型、取消沿用共用風格、另加文字及圖片。個別補充與共用描述共同送出；取消沿用後只送該物件資料。
3. 類型目前依概念家具類別、父物件及子物件名稱推定，未知列「其他」，不是圖像分類。牆壁／地板／門窗／天花逐子物件配對材質，不替換其幾何。送出前顯示物件數與實際目標數；每次最多 100 個目標，大案可按空間分批。
4. 圖片限 5 MB／2500 萬像素，清除中繼資料並縮至最長邊 1600 px；只供風格判讀，不作尺寸或商品真偽證據。需要支援圖片的 Codex 模型；所選描述、圖片與目標資料會送至該 Agent，使用相應額度。
5. 按「一鍵下載並配置第一版」即開始搜尋及自動下載套用：使用 Agent 排序後第一個合適的免費 CC0／Royalty Free 候選。下載前仍核對版本、價格、授權及大小。不自動購買、不自動使用付費候選。
6. 沒有免費候選時，保留用途與尺寸、放寬風格重新搜尋一次；下载／建模失敗則逐一嘗試其餘免費候選。每個目標都有狀態；查無素材、登入失效或全部失敗會保留原件與原因，不能宣稱全部成功。覆蓋所有選取目標不代表素材庫一定存在合適家具。
7. 三階段為「範圍與風格 → 第一版與備選 → 確認家具與清理」。結果可點「預覽／選擇備選」進入單物件展示。備選只保存來源連結及中繼資料，使用者選定後才下載。同清單在該物件替換後繼續有效；不允許套用到其他物件或非祖先模型。
8. 自動套用使用既有單一 Blender 佇列。進度保存於 `batches/<id>/placement.json`，每次工作有固定去重識別碼。重啟後按「核對既有工作並繼續」，先核對已完成工作，不重送下載。尚未完成的 Agent 搜尋中斷後不自動重跑雲端搜尋，可重新配置。
9. 若使用者另行修改設計，自動套用暂停並保留結果；不覆蓋新修訂。UI 有未保存修改時不自動載入新模型。停止後不繼續套用，執行中的 Blender 工作仍可能完成。

## 手動框選新增家具與裝飾物

02 編輯分為 **材質、裝飾物、光源、觀看點**。材質頁保留整屋家具「一鍵配置」；裝飾物頁只操作裝飾物，背景家具供定位。裝飾物操作列依序為「一鍵配置裝飾物、框選新增裝飾物、復原上一步」；光源頁對應「一鍵配置照明、新增光源、復原上一步」。一鍵按鈕會展開建議區、保存配置並接續 Agent 免費素材配對／下載；逐項結果直接列出。收合後仍在背景執行，不清理舊模型。

若要先調整空間、風格或天花高度，展開「自動建議裝飾／照明配置 → 配置範圍與風格」；「只預覽」不套用場景或下載。手動新增光源放在畫面平面中心、高度 2.5m，選中後於右側調整；它是獨立光源，不會自動下載燈具。

1. 在材質或裝飾物頁按「框選新增家具元件／裝飾物」，在 2D 拖出矩形範圍。右側確認名稱、類型、尺寸、所屬空間；範圍中心落在可見桌面等表面時，帶入其高度，仍可手動調整底部高度。
2. 選擇建立方式：輸入需求請 Agent 找模型、貼上 BlenderKit 單一模型頁連結，或先加入概念占位。新增後會保存修訂；搜尋／連結查核失敗也會保留占位，可在單物件展示重試。
3. 模型連結查核不呼叫 Agent；只接受官方 HTTPS `asset-gallery-detail/<UUID>/` 模型頁，不接受任意下載網址。顯示實際候選與授權後，沿用「選擇並替換 → 下載 → 套用」流程，付費模型不自動購買。
4. 新增元件可選取、平移、水平旋轉、刪除及復原未保存的上一步；已套用來源網址與新增需求保存於修訂。裝飾物替換模型後仍保留分類，不因素材名稱改變而離開該頁。

框選是占位範圍，不是精細碰撞或動線驗收；支撐高度使用可見幾何射線，透明物件、遮蔽與不規則表面需人工核對。家具先以通用類型建占位，最終素材保持比例，不保證填滿矩形。手動新增與替換不觸發舊模型清理。

## 儲存空間

- 採用第一版／備選時**不立即刪檔**。逐件檢視後按「所有家具已確認，清理未使用模型」。尚未成功替換的目標，必須逐項勾選保留原件，不能默默略過。
- 確認綁定當前修訂；之後再修改或替換，確認失效。案件仍有排隊／執行工作時暫緩清理。
- 清理目前版本的下载暫存、已被取代的 replacement 祖先版本，以及本批次失敗／未採用的替換工作大檔。保留目前 GLB／BLEND、原始匯入、照明來源、修訂 JSON、所有候選連結、授權及雜湊；不清除其他批次尚未採用的獨立工作。
- 最新 BLEND 移除不再使用的網格、材質及貼圖 datablock。已清理的舊模型標記不可再直接還原／出圖，但仍可從備選重新下載。
- 清理不是整案垃圾回收；既有渲染圖片與其他入口工作檔不在此範圍。

## 室內外照明與生活裝飾

- **02 編輯 → 光源 → 自動配置照明：預覽燈位**：依已命名地板的實際範圍安排天花燈位，指定距地板的天花高度，可勾選沙發旁落地燈。採用後新增天空環境、室外 SUN 日光與綁定燈具的室內光源。燈具模型由同一個 BlenderKit 批次搜尋、免費優先下載，不假設模型自帶可用光源。原有光源保留，避免覆蓋已調整設定。
- **02 編輯 → 裝飾物 → 自動建議裝飾配置 → 預覽裝飾位置**：依物件名稱／用途和可用範圍，為餐桌、書桌、茶几、床頭、爐台、水槽、洗手檯和沙發區安排花瓶、書籍、鍋具、餐具、洗手用品或地毯。只採用有支撐與可用空間的候選；可逐件取消。不會把未知家具名稱猜成可用檯面。
- **套用位置並自動找免費模型**：先保存概念占位與燈位，再沿用正常 Agent 配對與 Blender 替換佇列。每件結果、失敗理由、來源與備選可查。只有確實採用到場景才計入已替換；無合適候選保留概念占位，不假裝完成。
- **只重試未完成項目**：從當前修訂重新配對失敗項目，成功物件不重送。暫時容量不足或逾時最多嘗試三次；無免費結果再保留機能、放寬風格一次。不是無限重試。
- 燈具移動與旋轉會同步其光源。薄型吸頂燈以頂部貼齊設定天花，光源保持在底部之外。新增裝飾尺寸是可用範圍；既有家具仍保留功能高度保護，避免把餐桌縮成茶几。
- 匯入分散組件可在材質頁使用 **合併成單物件**。只合併原始模型且變換一致的組件，保存網格 ID 與光源綁定；不暗中改變家具位置。已替換素材與概念家具不能用此入口合併。
- 全部操作從 UI 呼叫共用服務，沒有案件 ID 或固定住宅座標。**配置位置目前是幾何規則，不是 Agent 看完整空間進行設計**；Agent 負責查詢與比較素材。名稱、空間歸屬、模型品質、可用素材與服務狀態會影響結果。
- 高度為使用者設定，非自動偵測天花。室外光是示意日光＋環境，尚無 HDRI 自動下載或基地日照分析；有無真正窗戶開口仍影響入室光。檯面使用包圍盒，未做精細碰撞／動線驗收。套用後請核對 2D／3D，再做低解析試圖。
- 不自動按下最終確認，也不清理任何歷史工作或下載；確認前可比較原版與備選。

設定保存在案件 `workflows/interior-studio/staging/<id>/`，記錄提案、採用修訂及批次。`POST .../staging` 預覽，`GET .../staging/current?kind=lighting|decor` 續開，`POST .../staging/{id}/apply` 採用，`POST .../staging/{id}/retry` 重試失敗項目。測試使用 `tests/fixtures/staging/` 合成模型，不打包真實案件。

## 平移與旋轉操作

在 2D／3D 選取家具，按「移動／旋轉」，切換平移或水平旋轉。可拖曳旋轉環、輸入角度或按 ±90°。旋轉以單物件中心為基準，家具保持直立；綁定光源的位置及方向同步旋轉。變更保存於修訂 JSON，網頁預覽及 Blender 出圖共同套用，原始 GLB／BLEND 不原地改寫。

## 帳號與限制

- 配對需要本機 Codex 的 ChatGPT 登入。搜尋與公開免費素材可不提供 BlenderKit key；若來源要求登入，設定自己的 `BLENDERKIT_API_KEY` 環境變數並重新啟動服務。不要把 key 放進案件、前端或 Git；應用不讀取 Blender 外掛的私人登入資料。
- 限 BlenderKit 官方素材服務，下載前重新核對版本、免費狀態與授權。價格或版本改變時要求重新配對；HTTP 錯誤、權限不足、缺貼圖或模型不相容均保留原場景。
- 單檔上限 150 MB、最多 500 個素材網格。材質資產必須能唯一辨認要套用的材質。只有 BlenderKit 的 `model`／`material` 可用；場景、HDRI、外掛或任意網址不是此入口。
- 有官方 2K 貼圖版本時優先下載該 Blender 套件，否則取原檔；下載雜湊與實際解析度版本另存來源紀錄。這可避免僅試用材質就下載大型 8K 原件。
- 保留原生 Blender 材質節點；GLB 只保留可匯出的 PBR 表現。程序材質、特殊節點及部分貼圖座標可能與 Cycles 不同；目前沒有自動完整烘焙。這是素材替換，不是寫實品質或動線驗收。
- 下載與建模沿用單一重型工作佇列；關頁後工作仍可查詢。編輯期間若版本變動，完成的替換不會覆蓋新設計。服務中斷不自動重新下載或提交高成本工作。

## 資料歸屬與整合

- 候選與來源：案件 `workflows/interior-studio/asset-matching/`。
- 每次替換：案件 `runs/interior-studio/<job-id>/`，含雜湊、來源、交接檢查及待採用場景；現用 GLB／BLEND 隨案件 runs 備份，不塞進 SQLite。清理後舊版本只留紀錄。
- 設計採用仍由不可變修訂 JSON 管理。新模型保留其他物件的 ID 與修訂操作，燈具綁定沿用原單物件 ID。
- 共用實作：`studio/asset_matching.py` 管理任務、過期檢查與採用；`asset_batch.py` 管理範圍、圖片及依序配對；`asset_automation.py` 管理可恢復的自動套用與最終確認；`asset_storage.py` 管理來源歷史與安全清理；`blenderkit_client.py` 查詢及有界下載；`visualization/asset_blender.py` 處理新模型；前端 `AssetMatcher.tsx`／`AssetBatch.tsx`。
- `POST /api/studio/projects/{project}/asset-links` 查核指定模型連結，回傳同格式候選與可重試的操作識別。只從官方 catalog 取得來源與下載資訊，不使用使用者網址下載檔案。
- `POST /api/studio/projects/{project}/asset-matches` 建立配對；`GET .../asset-matches/current?group_id=...` 續開。候選 `/reference` 保存來源，`/replace` 提交工作；`asset-replacements/{job}/adopt` 採用，`asset-replacements/restore` 受控還原。

參考：[BlenderKit 官方搜尋實作](https://github.com/BlenderKit/Blendkit/blob/main/search.py)、[素材授權說明](https://www.blenderkit.com/docs/licenses/)。本專案自行實作 HTTP 轉接，未複製官方外掛程式碼；第三方素材不因應用使用 MIT 而改變授權。
