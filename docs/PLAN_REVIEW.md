# 01 匯入：可複用的平面核對工作流

## 參考模型比對與幾何假成功防護（2026-10-29）

使用者明確指定參考模型為設計基準後，可在同一版本1證據包增補 `authority.mode=user_designated_model`、使用者原文及 `corrections`。每筆保存目標ID、原生來源綁定、模型物件、理由與量測值；先驗證整包及全部來源SHA，再原子套用。支援牆窗 points/base/height/thickness、未確認地板 points/holes、梁圖樣 model_dimensions（base、height、datum=model_finish_floor）。原生來源推導保留，另記 reference_geometry 與 reference_correction，避免重開又被DWG舊尺寸靜默還原。來源綁定不符、缺依據、已確認地板或既有孔洞變更皆阻擋；不能用此機制任意增刪物件。

人工答覆可由逐筆 `user_confirmation` 引用已列入 `reference_sources` 且經SHA核對的答覆檔及原文；與模型量測物件分開記錄，不能假造對應網格。只確認梁底時，`model_dimensions.height=null` 保存未知梁深，幾何檢查及物件交接仍列梁深缺項；不可用天花面推算梁頂，拆分物件中一筆尺寸完整也不能遮蔽其他缺項。局部地板收邊答覆不等於全案地板確認，仍維持原有確認／採用門檻；邊界修復後首次執行的入口問題另外顯示，不當成修改門牆造成的退步。

梁仍保留圖樣用途，已由模型證據核對的標高／梁深不再重複列為缺項；未能辨認獨立梁底時仍保留問題，不能因只看到天花面便刪梁。地板只接受已驗證參考修正內的局部支援線，與CAD來源共同核對；部分邊界有證據不代表整片樓板通過。GET與採用時重新驗證原件、平面版本及證據，採用重新載入CAD時保留同來源的參考證據；開頁不觸發修正模型呼叫。本功能確認的是使用者指定的模型設計值，不宣稱現場實測或施工驗收。

診斷版本為 `dwg-review-2`。`source_binding.overlapping_openings` 在來源推導完成後檢查實際洞口體積：同線重疊超過5mm且高度區間相交，無論名稱或宿主ID不同均阻擋。共端相鄰洞口、上下不同高度的氣窗不當作重複；窗扇／框的數量不能直接當成洞口數量。連續原生框線仍可推導整窗，但兩筆記錄推導成同一洞口不能各自算成功。

局部補丁若明確要求改座標，而來源綁定將其完全還原為舊形狀，會回報「幾何修正未生效」。需改選真正樘邊或處理重複表示，不接受只改 evidence 文字的修正。未選物件、原始來源及已確認地板的保護維持。

`semantic_reference.py` 支援案件持有的獨立參考判斷：`site.reference_evidence` 指向有SHA256的JSON，內含格式版本1、平面revision、`cad_candidates.source_hash`、參考來源路徑與SHA、配準紀錄及 findings。`prohibited_role` 只限制指定原生綁定的用途；`unresolved` 保留已定位差異，不自動移動座標。來源、版本或雜湊不能驗證時，保留來源阻擋。GET、續修及採用重驗使用同一規則，唯讀開頁不呼叫模型。拆合／換類保留 `object_links.semantic_lineage`，不覆寫辨識證據。

這不是自動SKP語意解析器：先核對原件／轉檔來源、量測配準殘差，再由明確可追溯的網格剖面與DWG原生來源建立判斷。不得使用整屋包圍框作配準、把材質飾面當樓板、把模型沒顯示的梁視為不存在，或把參考高度自動當作已確認施工值。案件指引／設定放本案 workflows，比對和正式證據留同案 run；共用程式不含案件ID或數值。

新增回歸：`test_semantic_reference.py`、`test_source_pair_continuity.py`、`test_cad_candidates.py`、`test_semantic_diagnostics.py`，包括授權缺失、整組回滾、確認地板保護、來源綁定變更、缺證據梁尺寸及重驗保持。實際案件證據留在各案私有紀錄，不隨程式發布。

## 分項檢查與有界續修（2026-10-28）

`semantic_diagnostics.py` 提供 `dwg-review-1` 唯讀診斷：來源與尺度、範圍、牆窗、物件幾何、物件交接、入口、來源覆蓋、人工確認。報告的 `diagnostics.checks/groups/issues` 與 `object_links` 為增補欄位；既有 status/errors/repair_errors、提交／採用 API 保持。passed 是任務處理完成，不等於設計通過。

- 原生 DWG 的既有地板與新外框均以原生邊線及牆帶核對，證據充分與使用者確認分開。已確認但證據衝突仍阻擋，確認紀錄與原地板不改寫。範圍不足時將相關越界集中成一組，原錯誤與受影響物件仍保留；不擴大容差。孔洞與非凸外框保持。
- 家具錯誤不再一律跳過入口檢查；地板、房間或相關結構有錯時明示 deferred，仍阻擋採用。局部修正使用穩定問題 ID 比較，前置修復後首次可檢查的新問題另記 newly_discovered，不當作原修正的回歸。
- 宿主牆、開口、引用同樘邊的 portal，以及來源關聯且實際相鄰的樘邊／上方牆體組成原子修正群組。局部包提供完整上下文；來源、宿主或相關越界未解時不部分採用群組，也不從失敗批次拆出一半。M/Q 的既有可改範圍不因上下文擴大。
- 整圖判讀後，範圍／來源、牆窗、物件／交接、其他來源候選按序接續同一個局部複核器；最多四批、每批24候選、兩次模型呼叫。不可拆群組超額時列待辦，相同候選及輸入不在該任務重試。各批保存輸入指紋及實際模型呼叫數，沒有額外第二套重試預算。
- object_links 以來源、類別和雙向實際輪廓重新驗證對應，按連通對應群組核對拆合；重複輪廓、漏對應或只覆蓋短線段均保留待辦，保存保留／拆合／排除／待確認及父物件資訊。共享來源ID本身不代表完成。舊模型候選與爭議保留；梁仍屬2D圖樣，標高／梁深是另需確認的建模條件。缺乏可驗證的舊排除紀錄不補造成功對應。
- 「繼續核對未解項目」沿用目前平面與判讀ID，明確關閉新YOLO推論並繼承經驗證的物件證據；來源變更拒絕過期基底。整圖重新判讀仍是另一個明確操作。重開頁面只讀，不呼叫模型、不改歷史。
- 主要操作欄分別顯示任務、檢查及採用狀態；分項待辦可展開、定位原圖。來源Q確認與Q/M編號沿用既有契約。採用前後端均重新檢查，未檢查不等於通過。

合成測試：`tests/test_semantic_diagnostics.py`，以及既有 plan_semantics、semantic_feedback、semantic_review、cad_candidates、batch_scope、YOLO pipeline 回歸；前端 `review-diagnostics.test.mjs`。私有開發案例 真實驗證另存本案 runs/plan-review，不作通用fixture；真實Agent完成及設計正確分開記錄。

## 物件／範圍局部反饋（2026-10-25）

M「批次修改所選」與Q「保存答覆並請Agent複核」均走`local-feedback-v1`：從目前物件與用途修訂套用局部補丁，不執行YOLO、全圖補漏、整屋候選或3D重建。「重新判讀整張圖面」是獨立操作；物件模型勾選不影響局部反饋。

- 從物件建立的M預設修整件，保存物件ID及圖層來源；也可改選僅標註範圍。一般新增M預設範圍模式。方框使用各框聯集；線條／圈畫為兩側各8公分，畫布顯示其範圍。文字不獨自授權修改位置。
- 範圍外幾何與類別保持。必要拆合保存`parent_ids`，原生來源裁切由程式記錄並於重開重驗；不可把開放CAD折線閉合成面、複製原件或順便加宿主牆。
- 新增必須有明確漏項／新增語句、種類、數量及位置，如「這裡漏了一扇門」。框內且來源合法仍不等於可新增。「此處不是牆而是梁」是原物件改類／拆分，不是任意加梁的許可。歧義、缺來源或缺未授權依賴保持待確認。
- Q按單項按鈕只提交該Q的答覆快照；其他已存答覆留作草稿，不當作此次全部修正。版本衝突拒絕套用；批次互相重疊的目標保留待確認，不能靠提交順序覆蓋。
- 每筆最多兩次提案，單項原子驗證。未選物件、其他待辦、圖層模式與視角保持。綜合物件及用途／建模表示無法一致時保留阻擋，不能僅因工作passed就聲稱修正完成。

既有提交API新增`mode:"feedback"`、`question_ids`及`answers_revision`；M沿用`correction_ids`並由後端強制局部處理。草稿新增`mode:"object|region"`及`target_domain:"objects|plan"`。舊M由有效物件ID判定整件；若既有標註已縮小到物件的一部分，改按該範圍處理，避免誤改整組。沒有有效目標時使用可靠標註，不回退整圖重畫。舊介面的Q請求缺少局部目標時拒絕並提示重新整理。

每次run保存`feedback/<序號>/request.json`、`scope.json`、局部圖、提案／拒絕原因及結果，另存`feedback-result.json`與物件圖層。來源、裁切、逐項結果與幾何有一致性摘要，GET及採用時重驗。舊版若遺失物件結果，只讀尋找同來源、幾何相容且凍結雜湊有效的祖先；不覆寫歷史、不重跑模型。既有`reconcile-batch`只服務舊版結果，新的局部反饋不得重播全屋候選。

實作核心：`semantic_feedback.py`。合成回歸：`test_semantic_feedback.py`及既有Q/M、來源綁定與經驗測試；不使用真實案件作通用fixture。

右上角 **Agent → 工作** 可查看目前判讀或Q/M修正任務、已提交的等待任務及已結束工作，另有「設定」分頁。側欄佔位，不浮在操作區；窄版展開時暫時切換為完整面板，關閉後恢復原工作區。列出目前階段、耗時、最近回報、批次範圍及失敗原因，每2秒更新；新工作只更新數量，不自動展開。Q仍由「保存答覆並請Agent複核」提交，M仍由「批次修改所選」提交；保存草稿不新增工作，仍沿用單一工作槽，完成後在原流程核對及採用。

可在Agent判讀設定勾選「使用物件模型協助核對」：先辨識全圖與重疊切片，再依原生文字／附近物件修正、套圖層、查漏及綜合判讀。結果可切換「綜合物件結果」與用途配置圖層；爭議建議保留原候選待辦，未自動採用。需先完成[本機模型設定](OBJECT_RECOGNITION.md#studio核對平面整合)，不勾選則沿用原流程。

所有者：共用匯入功能。圖片與電子平面共用此工作區，不依賴指定案件腳本。頁面維持 **1 核對平面 → 2 家具配置 → 3 建立 3D**；直接開啟3D仍走既有模型交接。

## 畫布與右欄

中央為原圖；用途分類移至畫布上的 **圖層 Legend**。可多選整組或細類，也可選Q疑點、M修改草稿；部分選取顯示半選。分類收合不取消勾選，圖層切換不重讀來源、不呼叫Agent、不改座標。預設勾選原圖參考，判讀、地坪與Q/M覆蓋預設隱藏；定位或編輯某項時暫時顯示它，仍可用「僅看原圖」清空覆蓋。

右欄只有 **物件／修正項／經驗庫**，可收合區塊預設關閉。移除堆疊的來源確認、概念預設、交接要求、尺寸對應及概念3D報告；原始紀錄與後端檢查保留。

- **物件**：只顯示目前點選的一件判讀物件、Q或M。物件參數及來源放在該物件內，依據區塊預設關閉；按「修改」建立帶來源物件ID與圖上範圍的M草稿，切至單項編輯。
- **修正項**：主清單與單項編輯分開，卡片保留名稱、一句意見及「待完成／已完成」「待採用／已採用」兩種狀態。新增其他M不重置已完成項，狀態仍綁定原意見與有效來源。保存成功返回清單，衝突或失敗留在編輯頁。清單支援「＋修改項」「批次修改所選」「批次進入經驗庫」。
- **經驗庫**：先顯示正式經驗及本案待確認卡的清單，點一項才進詳細頁，返回不在清單下堆疊表單。整理、保存、確認、停用與比對維持原功能；見[經驗庫](CAD_EXPERIENCE.md)。

完成核對的明確採用入口保留在畫布下方預設收合的「完成核對並交接」。切頁、隱藏報告或Agent完成都不等於採用設計。

## Q歷史與答覆

「修正項 → 疑點紀錄Q」保留現有與已解決的Q；也可從Legend點Q定位，右欄物件顯示原問題、原編號、答覆與確認狀態。歷次紀錄預設收合，可查看判讀任務、答覆修訂、保存時間及原始確認來源。相同問題／答覆／筆跡的重複保存合成一種內容版本，仍保留每次保存參照。GET不新建答覆、不重新確認。

Q身分採穩定ID，移除或解決前項不使後續重編。地板Q定位時顯示實際候選多邊形。已答Q不重問；明確清空的當版答覆不從歷史復活。原始Q框不能藉拖曳答覆覆寫。

來源Q的填答不等於確認；須明確勾選並保存。地板確認綁定原生來源、平面版本與幾何指紋，範圍改變即失效，伺服器拒絕舊target套入新候選。答覆及筆跡為資料，不是改已確認尺寸的許可。

## 修改與批次修正

1. 在物件按「修改」，或在修正項按「＋修改項」。可改名稱、意見，畫方框、兩點線條與文字；選取後能移動、調整端點、改字、刪除及復原。Q共用此編輯器並另有疑問與答覆。
2. 編輯畫布只處理當前Q/M的筆跡；其他物件仍供對照，不能誤拖。刻意點Legend或清單可切換目標，避免舊編輯狀態阻擋Q定位。縮放與平移仍可用。
3. 保存留版本快照，未保存內容在切頁保留。保存M後返回清單；純文字無可靠位置不捏造座標。草稿顯示與批次勾選為不同狀態。
4. 「批次修改所選」只帶選取項快照；先保存意見及Q答覆，再交頂端選定模型（預設gpt-6-sol）。空白項不能提交。來源／尺寸／必要家具及局部範圍檢查保留，未選區域保持。
5. 通過後更新候選圖面，逐項結果保留於詳細頁；失敗與待確認不冒充完成。沒有自動採用、入庫或清理。來源版本衝突拒絕套用；相同操作ID不重複建立任務。

「批次進入經驗庫」只接受已保存、同版有效完成的勾選M；此按鈕是使用者對所選修正的明確入庫授權。Agent合併同類錯誤的判讀條件，不同問題分開，保留各案局部圖、原生幾何及註解；未選項不能混入。它不採用平面設計。單卡仍須個別勾選確認。

## 判讀與檢查邊界

保留來源及數字尺寸優先，手繪線長僅供相對位置。DWG讀取原生圖層、文字與元件，與衍生DXF交叉核對。盤點用途、牆門窗及原圖已有家具；沒有家具才進AI空間配置。未確認尺度、來源疑點或幾何衝突仍阻擋採用與3D。

`cad_candidates.py`盤點用途文字、門弧、平行框線、原生輪廓及圖塊，合併重複線索，不把填色／尺寸線拆成家具。來源處理狀態、局部複核及工具錯誤保存在run，不在右欄堆報告；統計不是CAD正確率。

`semantic_local_review.py`每輪最多24組、每工作4輪，每輪最多2次Agent呼叫；提供原圖、最多6張局部圖、幾何與有效答覆。程式檢查來源綁定與變更範圍，逐項隔離合法修正；提出Q前再查已有資料。工具錯誤／逾時不冒充需要人答的Q，模型失敗不切供應者。

同來源後續判讀漏帶已確認垂直尺寸記錄時，只從同版祖先恢復有雜湊與原文綁定的確認；讀取不寫回候選。相同原生幾何及已批准height/base更新可沿用M歷史，不能放寬位置、厚度或未確認尺寸。

## 配色、資料與共用實作

畫布淺／深色只調預覽對比，保持線型、填色、原座標；圖片不反色。偏好保存在瀏覽器`roomweaver.plan-review.theme`；切換不重讀CAD、不改Agent輸入或材質。

原件在案件sources；轉換run與原圖快取在runs；判讀、答覆、草稿及採用紀錄在`workflows/plan-import/<plan>/semantics/`。M保存於`corrections/<source_revision>/current.json`及不可變revisions；Q答覆在各判讀run的answers。每次批次保留選取快照、標註圖及逐項結果，不是可清理快取。

共用前端：`PlanSemantics.tsx`、`SemanticSourceReview.tsx`、`SemanticLayerSelector.tsx`、`SemanticCorrections.tsx`、`SemanticDraftDrawing.tsx`、`CorrectionExperience.tsx`；位於`frontend/src/features/visualization/`。後端：`plan_semantics.py`、`semantic_corrections.py`、`question_history.py`、`experience_batch.py`等，位於`src/interior/workbench/studio/`。

驗證使用獨立合成資料（`test_experience_batch.py`及既有來源／修正／經驗測試），瀏覽器以真實案唯讀核對；真實案證據不進通用fixture。Agent整合、經驗確認及設計採用各自驗證，不能互相代替。更多限制見[匯入標準](INTAKE_STANDARD.md)與[DWG讀取](DWG_READING.md)。

# 批次修正範圍與既有判讀保留

M批次修正是局部更新。程式端依本次勾選標註及相鄰宿主關係限制變更，範圍外既有區域、家具、門窗、燈具、圖樣及Q保持；範圍外新增提案／疑問不套用。涉及延伸宿主時，實際幾何改動須留在選取鄰域。保留既有高度／離地、必要家具及原始尺寸，未採用平面不變。

來源處理紀錄不再由整份候選hash一變就全部作廢。沿用前先核對原生來源版本及每筆候選指紋；有變動的物件引用重新核對，未變動者保留mapped／ignore／question紀錄。mapped每次仍驗證實際物件，跨段框線須由多段已定位洞口及相鄰牆體共同覆蓋才能視為已處理，不能拿單一引用假裝完成。原有工具失敗原因保留，不能轉成重複的人工作業。

舊版已完成批次若因這個問題丟失來源紀錄，原M草稿及來源均未改時，再按同一個「批次修正所選」會走reconcile-batch：沿用已完成的Agent提案，重新套用共用範圍／來源檢查，產生新的預覽版本，不再次呼叫模型。前後原始任務留存；經驗卡保留ID及編輯內容，以版本快照更新預覽關聯，不確認入庫或採用。若原圖、單位、草稿或來源版本不同，拒絕套用舊結果，改走正常判讀。

實作：semantic_batch.py、cad_candidates.py、semantic_local_review.py、plan_semantics.py。新案合成回歸測試：tests/test_semantic_batch_scope.py；不依賴私有開發案例的腳本或ID。


## 已保存修正提案的重驗

同來源、同平面版本、同一組修正項且內容未變時，重試先重新驗證保存的Agent提案與局部判斷；不是信任舊的完成宣稱。新增其他草稿不會迫使重做全屋。保存重驗使用的原始回覆路徑及逐項接受紀錄；來源、圖層讀取版本或選取內容不同就不沿用。不能從快取自動採用設計、提出未再次查證的Q或確認經驗。

連續原生窗框片段及不相容的窗宿主依同一原線核對；只修正實際不相容且在本次範圍內的窗，不延伸原本正確的其他牆。已經局部複核、來源一致的玻璃門／隔屏符號可對應原生開啟弧，不因不是房門模型而反覆列漏判。

家具可依原生邊使用`edge_bounds`推導概念區域：精確選取四條LINE／直邊LWPOLYLINE的相對正交圍護邊，依朝向使用區的原生內緣形成矩形（可隨圖面旋轉）；與取整件來源元件的`bounds`分開，避免將開門弧或柱體的整個範圍誤作設備占位。只適用家具概念區域，不可代替牆門窗綁定。被選到的過大設備可縮回同組原生來源，不因此放寬移動其他物件或已確認高度的限制。


## 逐標註修正核對（2026-10-22）

牆與櫃體緊貼時分別辨識：櫃體註記不能代替背後牆帶，核對原生填色、厚度、連續端點及家具外輪廓。初次判讀及局部複核共用此規則，不依案例ID。

新M批次的每筆方框、線條、文字須各有`mark_results`，含mark_id、狀態、預期用途、實際物件ID與理由；不能以來源ID已引用或整項口頭成功代替。來源綁定及範圍保護後再核對用途與位置，細長牆框核對實際牆段聯集的長度覆蓋（80%為手繪框留白容差，不是設計準確率）。缺項、重複、錯類別、錯位置或只補端柱皆保持待完成，隨錯誤送回有界Agent重試。未完成不可產生成功經驗卡或自動採用。

詳細編輯顯示每筆標註的核對結果；選取多筆草稿時用M序號.標註序號對照。舊牆類完成宣稱於讀取時依當前幾何再查，不改寫歷史來源或完成回覆。其他舊項保留既有紀錄，新執行才使用逐標註契約；這不是舊項已補做完整複核的宣稱。

實作：`correction_regions.py`、`semantic_corrections.py`、`plan_semantics.py`。回歸：`tests/test_correction_regions.py`，使用獨立合成牆櫃及跨標註漏項，不含真實案圖。


## 牆交接與柱體（2026-10-22）

牆端、轉角、交接處須盤點柱體與加厚構件，不能以附近長牆已引用來源取代其辨識。粗線、方形填色、厚度變化只是線索；合看閉合輪廓、雙邊實際厚度、相鄰牆連接、註解與已確認意見，不能將每個厚矩形都當柱，等厚T形／L形接續也不能憑空增柱。

為沿用既有3D交接，結構構件仍用role=wall，category=column或wall_junction在牆體圖層內獨立篩選。已存在的構件沿用ID；原生封閉凸輪廓可用outline完整保留斜邊，不能強制pair裁成等厚矩形。牆端柱與交接不可重複建模，與相鄰牆、櫃體分開；凹形輪廓仍需分段，不能改原點或推論承重與可拆性。

逐標註核對同時檢查柱體用途及實際占位，框內僅有一條薄牆不算完成。這些規則放共用初判／局部複核prompt及來源綁定程式；案例經驗仍依明確人工入庫要求與來源版本檢查，不從自動候選擅自確認。


## 實心填色與輪廓交叉核對（2026-10-22）

同處原生填色與封閉多段線可能互相矛盾；native_exact只證明資料可追溯，不能證明所選輪廓符合可見圖面或已確認用途。柱體／交接構件的outline若與接近同範圍的已驗證實心填色有2mm以上邊差及面積差，保持待修正並回報兩種來源，不以95%框內覆蓋冒充完成。

LibreDWG與DXF一致、單一閉合直邊且無孔洞的SOLID HATCH可標為native_exact_fill；僅柱體／交接構件可使用solid_outline，仍依原圖、鄰接及有效人工意見選擇，不一律優先填色、不將曲線填色或一般地坪當牆。原件不修改，實心邊界原點沿用；正常輪廓與填色一致不重問。

增加核對證據旗標及閉合環的起點／方向重編碼不代表改圖；同來源比較允許相同閉合幾何的循環編碼，仍拒絕實際點位改動。未選物件、M完成紀錄及來源處理不因證據升級而清空。舊版同批次可經reconcile-batch重驗恢復有效紀錄，保留原執行與錯誤經驗停用記錄。

實作structural_evidence.py、native_intake.py、source_binding.py及來源／逐項完成檢查。測試test_structural_evidence.py使用合成矩形填色與斜多段線衝突，不含案件資料。


## 交給02前補齊與概念3D預覽

交接準備、門窗規格、功能子項及尺寸紀錄仍由後端保留與檢查，不在核對平面右欄顯示報告或概念3D。既有預覽紀錄不刪除；實際3D沿用上方第三步。七組範圍、原生門楣與未知高度規則見[交接標準](INTAKE_STANDARD.md#七組02交接補齊與未採用預覽2026-10-22)。


### 使用者補充的垂直尺寸與原圖未註明線條

原圖存在但用途未註明的線條應保留原輪廓並列Q，不直接推定成梁、拆除或天花邊界。新確認的矮牆／窗台／窗高分別保存，與原圖文字要求分開追溯；來源原文位於案件sources，解析及適用範圍位於workflows。確認後的height/base可在右側標為使用者已確認；只允許雜湊綁定的使用者確認紀錄維持既有Q/M完成歷史，未授權的位置、厚度或其他物件高度變更不能藉此繞過檢查。


### 隱藏疑點與查看原圖

「顯示類別」新增「待確認疑點」：未填答的Q也可逐項或全部隱藏，其框、標籤與答覆草稿共用顯示狀態。定位Q或新增標註時會重新顯示該項；隱藏不刪除問題、答覆或確認紀錄。「僅看原圖」關閉判讀、Q/M草稿及地坪外框，保留原始CAD圖層與當前視角，以完整亮度顯示原圖；重新勾選類別及疑點可再疊合核對。

Q疑點與M修改項草稿使用相同分類列：整組勾選框、部分勾選狀態及右側展開／收合按鈕。收合僅隱藏子項清單，不改變圖層勾選、圖面或已保存紀錄；展開後仍可逐項勾選。


Q疑點解答後保留原編號，不因前項移除而重編剩餘問題。地板疑點點選時會顯示實際候選外輪廓，定位外包框不等於地坪形狀；原文意見只有明確確認才會接受範圍。天花梁的平面用途可先確認，尚未確認標高及樑深時以2D與交接要求保留，不轉成落地家具概念方塊。
