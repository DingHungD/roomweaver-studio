# DWG 原生讀取與座標核對

2026-10-21。所有者：共用CAD匯入。原生讀取已接入01的DWG上傳與Agent判讀；來源保全、分層／註解、綁定幾何、自動複核及原圖疊合共用於新案。讀取成功不等於設計確認。

## 01正式流程

1. 上傳保留DWG，ODA僅產生工具可處理的DXF；LibreDWG直接讀原件。依識別碼核對原生與DXF的選定欄位，幾何／圖層不一致阻擋。未支援類型另列未驗證，不冒充完整相容。
2. 保存實際單位後按Agent判讀／對照原圖自動複核。舊案在判讀時補讀原件，不改舊平面修訂。圖層、文字、尺寸、原生弧及群組進入同一資料包；文字是資料，不執行其指令。
3. Agent分類元件並給`source_binding`，程式由原生邊線計算位置，不使用Agent重填的物件座標。用途區域仍為判讀候選。圖片與直接DXF沿用原流程。
4. 01保留「核對平面／家具配置／建立3D」三階段；核對平面以單一原圖畫布與右側操作欄為主。圖層與疊合收於畫布選單，預設合看所有圖層和文字。實線為來源，虛線為候選（牆綠、門橘、窗藍）；滾輪只縮放圖面。
5. 原生流程最多三輪Agent複核。已定位且確需人工的問題保留，不任意切洞。採用時再次重讀／核對來源圖與雜湊，拒絕舊版未綁定DWG候選；採用新增修訂，確認後才基本3D。

原件座標不變；牆中心線／門洞軸是可追溯的衍生幾何，不等於原始門扇線。洞口可在真正牆厚內，不能為對齊錯牆而移動原門。切洞只作用於指定宿主，保留原軸並切穿完整牆厚。

## 原圖與建模幾何分離（2026-10-21）

核對平面的原圖改由 `cad_source.py` 的來源繪圖器產生。DWG仍由LibreDWG直接讀取與核對，顯示則使用已核對的來源DXF，保留繪製順序、曲線／弧線、polyline線寬、填色／圖案、尺寸及文字。每筆顯示路徑帶原圖圖層與識別碼；不從可編輯的 `parsed.features`、推定地板或採用候選重畫原圖。

- 建模用的地板凸分片、長曲線三角分片及 `SEMANTIC` 輪廓不能作為來源。Agent幾何另從原始CAD路徑讀取，不連接不同路徑，不將隱藏圖層或不可見元件當作可見原圖物件。
- 新匯入尚未判讀時即可看來源向量。判讀前後共用此繪圖器；`顯示判讀疊合（非原圖）`預設關閉，候選只在明確開啟或判讀分類頁中顯示。
- 主圖預設配合文字／尺寸範圍置中；「顯示完整原圖」可查看原DWG本來就存在的圖框、標題欄及遠處參考筆畫。這些不是新增的建模物件。
- SVG到疑點圖的轉換使用保存的比例、原點與座標矩陣，滾輪、拖曳及Q答覆沿用同一來源位置。不得為了讓兩張圖看似相同而修改來源點。
- 顯示快取在案件 `runs/cad-source-preview/<來源與版本雜湊>/source.json`；可從原件重建，不改平面修訂或原件。`GET .../plans/{plan_id}/source-drawing`為唯讀入口，不啟動Agent。
- CAD中文bigfont缺少時，選擇本機確實含所需字形的中文字型，記錄替代情形；不把缺字方框冒充完整文字。線型、字型、外部圖像及進階CAD物件仍可能與原生CAD軟體有顯示差異，未宣稱完全等價。

Agent的來源圖亦由相同SVG擷取為PNG，保存在新判讀run中，不覆寫舊run。此步需要已安裝agent選用依賴及Chromium（`pip install -e ".[agent]"`、`python -m playwright install chromium`）；純瀏覽來源SVG不需要瀏覽器執行器或模型帳號。

來源幾何版本為 `source-only-v2`，原生綁定為 `source-bound-v2`。舊候選不原地改寫，也不拿舊版來源候選直接採用；重新複核後才可採用，已確認設計／尺寸保留。測試見 `tests/test_cad_source.py` 與 `frontend/tests/cad-source-projection.test.mjs`。實際Chromium擷取和模型判讀分別記錄。

## 核對平面操作

共用操作與交接順序以 [平面核對工作流](PLAN_REVIEW.md)為入口，適用新專案。畫布上方可選「淺色／深色」：來源 CAD 線色與背景配合提高對比；僅改瀏覽器預覽，原件、Agent 圖像、座標及材質不變。切換保留縮放、圖層、Q 定位及未保存答覆，重開沿用瀏覽器偏好。

- 右側「疑點」點 Q1／Q2 卡片，或直接點原圖 Q 框，放大到待確認位置。
- 選「A → B 端點」依序點兩點；選「圈畫」按住拖曳。可復原上一筆，Esc 取消未完成筆畫。移動圖面模式可拖曳平移。
- 填寫「答覆／標註的意思」，保存答覆，或按「保存答覆並請 Agent 複核」。可部分回答，未回答繼續保留；保存本身不呼叫模型。
- 「判讀結果」集中顯示必須確認的用途區域、牆門窗，以及原圖有畫才判讀的家具。家具以整件來源組合判讀，不把填色或斷線當獨立家具。檢查錯誤不重複當成人工疑點。
- 判讀結果以「顯示類別」下拉多選「用途區域、牆體、地坪、門窗、家具、設備、燈具、裝飾物」；有未分類圖樣時加「其他」。可跨組及細類合併顯示，組別提供半選提示。家具可篩櫃子、椅子、桌子、電視、床等；設備包含廚具、衛浴及家電，裝飾物包含植栽、地毯、窗簾、掛畫及擺飾。這是用途分類，不修改DWG原始圖層，也不因分類新增物件。
- 程式待修正原因與Q答覆分開：「自動檢查待處理」只列`repair_errors`，沒有程式錯誤就不顯示空區塊；Q仍保留在疑點清單並阻擋未確認採用，不因隱藏空區塊而通過檢查。
- 勾選一個或多個類別顯示對應判讀內容，可勾選淡化原圖參考。點清單定位，點圖樣同步清單與來源說明。地坪各部分在同一瀏覽群組中，真實孔洞保留；參考邊界仍標示待核對，不能因顯示就當作確認。
- 燈具圖樣新增 `lighting` 盤點，必須引用原圖幾何，可附文字佐證。原圖「需要崁燈」等只有文字的項目，顯示虛線燈號定位**文字本身**，不宣稱燈具位置或數量；舊候選尚未盤點時會明示。尚未產生真實光源或新燈具模型，仍交02光源編輯。
- 額外裝飾／設備／柱梁圖樣可用 `drawing_objects` 引用來源幾何，分層及類別一致才接受；不把註記當成實物。這份原圖盤點不自動增加3D、採用素材或改寫家具配置決策。`elements.category` 提供Agent用途分類；舊候選可依名稱／既有用途作顯示分類，未知保留其他。
- 右欄為「判讀結果／修正」；模型統一沿用頂端「Agent 設定」，原圖補充與重新複核在「修正」，首次判讀入口保留於「判讀結果」；舊「單位、尺寸與進階修正」已移除；未確認尺度改於匯入當下以對話詢問，地板及其餘來源警示則合併到現行 Q 清單，不另列「確認來源」。不刪除來源、尺寸綁定或已確認記錄。判讀結果與修正共用圖層及視角，M/Q 共用可移動、調整端點／改字、刪除、復原的標註編輯器。物件依據與候選高度等預設值只在選取後的右欄詳細資料顯示，不另列全案「判讀依據／概念預設」。未確認尺度會阻擋判讀；來源Q需明確確認，採用及建立3D仍保留原檢查。

現有Q的答覆／筆跡會同步為「修改項草稿」圖層，可在結果下拉或草稿清單多選顯示並定位回修正頁；圖層顯示不改CAD或提交Agent。使用者亦可新增 M 修正項，框選／畫線／放置文字，勾選後交 Agent 批次修正並逐項回報。完整操作與版本/API 規則見[修正項與批次修正](PLAN_REVIEW.md#新增修正項與批次修正第3項)。

答覆 API 仍為 `PUT .../semantics/{task}/answers`，新增 `annotations:{question_id:[{id,kind:"box|line|text|freehand",points:[[x,y],...],text?:"圖上文字"}]}`。座標為該來源版本的局部公尺 XY、Y向上，不是螢幕像素。每題文字與筆跡一起保存至版本化 `answer-revisions/`；檢查來源修訂、答覆修訂、已知Q編號、有限數值、原圖範圍與總量。舊純文字答覆相容。

下一輪請求帶入精確標註座標和新增的 `answer-annotation-*.png` 圖片；原圖與既有平面不改。已解答的確認在同一來源版本後續複核繼續沿用。筆跡不是新牆或尺寸的自動採用指令，含意不明仍須釐清。

測試：`tests/test_semantic_answers.py`、`frontend/tests/semantic-source.test.mjs`。實際圖面操作、合成多Q保存重開及測試模型輸入分開驗證；未把合成Agent回應當成真實辨識成功。

語意分層：`semantic_layers.py`／`SemanticLayers.tsx`；測試見 `tests/test_semantic_layers.py`、`frontend/tests/semantic-layer-filter.test.mjs`。CAD轉換處理仍在背景執行；原「CAD自動整理」不再作為主要功能，必要單位確認保留在進階區，其餘轉換統計收於證據。

## 來源綁定與自動修正

`source_binding={method,refs:[{id,edge}]}`，邊索引從0開始；封閉最後一邊接回0。

- pair：原生平行邊的中間軸，取實際重疊長度；牆厚由實際間距推導。
- between：兩側門／窗樘相對內緣的中點之間，不拿門扇線當洞口。
- portal：已綁定洞口上方宿主牆，必須與對應between門窗共用同兩側樘；避免把縱向門誤接橫向鄰牆。
- outline／bounds：家具原始凸輪廓／來源組成的概念包絡，保留必要家具。

程式可由同一薄輪廓的真實長邊修正端頭誤選；接續且共線的窗框LINE可整合。窗扇交疊區太短時，只有原始外框與兩端收邊足夠才補齊整窗，跨越完整中間分隔不得合併相鄰窗。原始refs保留，推導refs與自動修正另記derivation，重複核對不逐次放大。原生開門弧＋兩側門樘及平行框線只產候選，仍由Agent對照原圖判別用途，不以圖層名稱代替辨識。

`native_intake.py`按來源／DXF／讀取工具雜湊保存`runs/dwg-reading/import-*/`，索引用於重送去重。不可在修訂仍引用時清理。判讀請求保存native_dwg、精確元件、註解與來源版本；採用的SEMANTIC元件保存source_geometry。沒有新DB或付費服務。

## 免費方案

- [LibreDWG](https://github.com/LibreDWG/libredwg)：dwgread 直接解碼 DWG 為 JSON，保留識別碼、圖層、座標、文字、尺寸、圖塊與外部參考。實測官方0.14 Windows x64；屬GPL-3.0-or-later獨立工具，不是本repo的MIT元件，不打包其binary。官方說明部分進階物件可能略過，不保證所有DWG完整支援。
- [ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter)：現有免費本機轉DXF路徑。DXF也保存圖層，不能假定轉檔就失去分層。
- [DWG TrueView](https://www.autodesk.com/products/dwg-trueview/overview)：免費人工核對原始顯示／圖層的選項，不是已實作的自動化介面。

## 唯讀工具

核心：src/interior/workbench/studio/dwg_inspection.py。LibreDWG另行安裝，指定實際執行檔，不上傳圖面或自動切換付費服務。

```powershell
python -m interior.workbench.studio.dwg_inspection path/to/input.dwg `
  --reader path/to/dwgread.exe `
  --output path/to/project/runs/dwg-reading/new-run `
  --dxf path/to/derived.dxf
```

output必須為新目錄；dxf可省略。輸出native.json原始解碼、inventory.json圖層／原生文字／尺寸端點及覆寫／群組／圖塊、manifest.json來源工具雜湊與原件未變檢查，以及讀取日誌。指定DXF另產dxf-comparison.json，核對模型空間識別碼、圖層與選定幾何／文字定位／尺寸欄位。未知類型列為未驗證，不冒充通過；不是所有字型、填色、視埠與CAD欄位的完整等價驗證。

目前不展開INSERT世界座標，也不把圖塊內文字全當需求；圖塊／變換保留於JSON。進階圖塊、傾斜OCS等無法安全處理時仍阻擋，不宣稱所有DWG皆可直接建模。獨立唯讀CLI不改現行修訂；UI採用則經確認新增修訂。

## 匯入原則

1. 原生座標、識別碼、圖層與群組／圖塊為權威；Agent分類組合來源，不從圖片重填精確座標。
2. 門洞綁定門樘、門扇／弧線及牆面。僅引用正確ID不足以證明位置正確。
3. 牆／門洞中心線是衍生幾何，與門扇線不同；保存推導關係及偏移檢查，不任意投到候選牆。
4. 圖層不是用途字典；混層、家具弧線、圖框、尺寸圖塊及外部參考分開處理。
5. 電子CAD不套用手繪任意直角校正；保留已確認數字／單位，分開保存尺寸端點與覆寫。
6. 原生檔、DXF、判讀候選、建模結果分層核對；未解外部參考及不支援物件明示，不默默丟棄。
